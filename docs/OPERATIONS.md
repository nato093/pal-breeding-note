## 共通パスワードと ID

- 更新後、所有者が Apps Script エディタで `setup()` を再実行する。`設定`・`Users`・`Users_test` シートと保護されたヘッダーを追加する。既存の配合データと設定値は変えない。
- 本番の共通パスワードは `設定` シートの `項目` が `共通パスワード` の行の `値` に保存する。初回は旧 Script Property `PASSCODE` を移行し、旧プロパティを削除する。旧値がなければ自動生成する。値はログに出さない。
- 変更するときは、そのセルを直接書き換えて利用者に新しい共通パスワードを伝える。値の列は書式なしテキスト（`@`）を保つ。数字だけの値も文字として入力する。
- 照合は前後の空白を除いた完全一致で、大文字小文字・記号・日本語を区別する。設定が空、シートや行がない、テスト値が空、両者が同じ場合は全リクエストを拒否する。
- `Users` は本番の ID 一覧、`Users_test` はテストの ID 一覧。列は `userId` / `createdAt`。利用者は画面の新規登録から ID を追加する。ID は制御文字と前後の空白を除いた1〜20文字で、全角英数や大文字小文字が違っても同じ ID とみなす。
- ID の確認・削除は該当する Users シートで行う。削除した ID の端末は次のデータ取得時にログアウトする。配合レコードの登録者名や既存レコードは変わらない。
- 利用者は設定画面の「ID を変更」（ヘッダーの ID のメニューにもある。2026-10-14 の copy-dead-ends の前は「名前を変更」）で自分の ID を変えられる（API の `rename`）。Users の行と、配合レコードの登録者名（削除済みを含み、全角英数や大文字小文字の違いも同じ名前とみなす）、OwnedWorlds の `uploadedBy` を新しい名前にそろえる。`updatedAt` は変えない。
  - Log には同じ `recordId`（操作の opId）で開始の `rename` と完了の `renamed` の 2 行が残る。`rename` だけの行は途中で止まった変更で、利用者が設定画面の「ID の変更を再試行」を押すと続きから行う。過去の Log の行は書き換えない。
  - 旧名は予約しない（ほかの人が新規登録できる）。旧名のままの別の端末は、次のデータ取得時にログアウトする。大文字小文字・全角半角だけの変更なら、ログアウトせず新しい表記にそろう。
  - 共通パスワードだけで動くため、画面を通さなければ他人の名前も変えられる（既存の配合の更新と同じ水準）。
- パスワード変更後は次の API 通信で再ログインが必要になる。端末には成功時の ID とパスワードを保存する。設定画面のログアウトでパスワードとキャッシュを消去し、次回入力用の ID は残す。
- テスト用は従来どおり Script Properties の `TEST_PASSCODE` を使う（AI・開発者専用）。`.env.local` の `PAL_TEST_PASSCODE` に保存する（コミットしない）。必要な場合のみ `TEST_PASSCODE` を消して `setup()` を再実行すると作り直される。

## 配合を探す

- 配合検索・逆引き・一覧は、2026-10-15 に 1 画面「配合を探す」（`#/search`。`web/js/views/search.js`）にまとめた（README の D1。find-merge）。引くのは登録済みの記録だけ（INV-2。`web/js/core/record-search.js`）。
- 条件はヘッダーの下に固定した帯で選ぶ: 1 段目 [親1] ＋ [親2] → [子] とキーワード、2 段目 登録者・並べ替えと、右端に件数。親 2 体ならその組、親 1 体ならその親を使う配合（親1 でも親2 でも）、子だけならその子の配合、親と子なら「その親と何を組めばその子か」。何も選ばなければ全件（既定は更新日の新しい順。D6）。
- キーワードは親・子の和名（ひらがな・カタカナはそろえる）・英名・図鑑番号・登録者・メモで、空白で区切るとすべてを含むもの。登録者は「すべて」・自分・ほかの登録者（件数の多い順。名前の変更の前の古い名前も）・登録者未指定で、12 人を超えると検索つきの選択になる。
- 並べ替えは 更新日の新しい順・親の図鑑番号順・親の五十音順・子の図鑑番号順・子の五十音順。親・子の並びは 1 件 1 回で、「No.1 モコロン · 3 件」の見出しの行の下に短い式（親の並びは「相手 → 子」、子の並びは「親 ＋ 親」）でまとめる（前の一覧の「1 件を親ごとに 2 行」はやめた）。親を 1 体だけ選んでいれば、その親の見出しにまとめる。
- URL: `p1`・`p2`・`c`（パル ID）、`by`（登録者の ID）、`noreg=1`（登録者未指定）、`sort`（既定の updated は書かない）、`q`（キーワード。入力では履歴を増やさない）。前の `#/reverse?c=X`・`#/list` は、履歴を増やさずに `#/search?c=X`・`#/search` に書き換える（ブックマーク・保存済みの通知の href も同じ。`web/js/router.js` の `canonicalHash`）。
- 件数の行は「N 件」。親 2 体で同じ組に結果が複数あれば「· 同じ組み合わせで結果が複数あります」、すべての記録に親の性別があって子ごとに向きが違えば「· 親の性別で子が変わります」。親を 1 体だけ選んで 6 件以上なら、子ごとの件数のチップ（押すと子で絞る・もう一度で外す）を出す。0 件のときは、選んだ親・子を入れた登録の入口（「この組み合わせを登録」など）か、登録者・キーワードのときは「条件をすべて解除」。
- 所持の重ね表示（2026-10-15。owned-overlay）: 所持パルのデータがあれば、カードの親の絵の下に親にできる個体の数「♂2 ♀1」（0 体なら薄い字の「未所持」、タマゴ・グローバルパルボックス・性別不明だけなら「タマゴ等だけ」。全文は title）、子の下に「所持 N」を出す（押すと所持パルをその種族で開く）。帯の 2 段目の「所持」の切り替え: 「両親を持つ組を上へ」（`ownedfirst=1`。今の所持で両親を別々の個体の ♂ と ♀ で組める記録を、並びの中で先に。記録に親の性別があればその向きだけ）・「今の所持で作れる」（`make=1`。組めて、子をまだ持っていない記録だけ）。集計は `web/js/core/owned.js` の `ownedCounts`・`canPairRecord` で、所持パルのデータが変わったときだけ数え直す。

## 所持パル（セーブ連携とスプレッドシートでの共有）

### 共有の世代とセーブの識別（2026-10-16 追加。sync-fixes の owned-gas）

GAS の共有の書き方を「シート全体を消して書き直す」から**世代ごと**に変えた（`gas/Owned.js`。設計は `docs/sync-fixes/README.md` の 3）。

- **書き込み（F1）**: 鍵の中で ①新しい世代の行（`updatedAt`＝サーバーの時刻）を `OwnedPals` の最後の行の下に足す → flush → ②`OwnedWorlds` の行の `uploadedAt` をその時刻にする（ここで公開）→ flush → ③そのワールドの「今と 1 つ前」以外の世代の行を塊ごとの `deleteRows` で消す。他のワールドの行は触らない。シートの行数（`getMaxRows`）が足りなければ `insertRowsAfter` で 1000 行の余裕をつけて足し、行を消すときは同じ数の空の行を末尾に足し戻す（シートの行数は減らさない。巻き戻し先の版 10 は行数を足さずに全部の行を消してから書き直すので、行数が足りないと消した後の書き込みに失敗して共有が空になる。読み手の範囲が行数を超えないためでもある）。
  - 読む側（`owned`・`ownedSince`）は `updatedAt` が `uploadedAt` と同じ行だけを使う。数が `palCount` と違えば（読む途中で読めなかったときも）1 回だけ読み直し、それでも違えば再試行できるエラー `PARTIAL`（画面は「共有の書き込みと重なったため…」）。シートの行を直接消したときも `PARTIAL` になる（次の共有で直る）。
  - ③が失敗しても共有は成功のまま（応答の `cleanup: false`）。残った世代・②の前に落ちた行（公開されない孤児）は、そのワールドの次の共有（書かない結果でも）で消える。`OwnedPals` には、そのワールドの行が一時的に 2 世代分ある。
  - 削除（`ownedDelete`）は先に `OwnedWorlds` の行を消し（公開をやめる）、その後で所持パルの行を塊ごとに消す。
- **セーブの識別と結果の種類**: 画面は送る `world` の中に `saveStamp`（`Level.sav` の中の保存時刻の生のティック）・`contentHash`・`format`・`fileCount`・`missingCount`・`force` を入れる（2026-10-16 の share-upload から送る。最上位の項目は増やさないので、古い GAS は捨てるだけ）。`contentHash` は送る中身の SHA-256 の 16 進（画面の `crypto.subtle`。元の文字列は `web/js/core/owned.js` の `ownedContentText` で、`[worldId, ワールド名, ホスト名, ゲーム内の日数, players, bases, farms, columns, rows]` の JSON。識別の項目・送った人・`saveUpdatedAt`〔同期で変わる更新日時〕は入れない。並びによらないよう、行は行の JSON の順〔先頭が個体 ID〕、players・bases・farms は要素の JSON の順、object は鍵の名前の順に並べ直す〔個体の並びは登録したファイルの順で変わり、PC ごとに違うことがある〕。セルは文字列。古い GAS に合わせて列を狭めて送るときは狭めた後の中身）、`format` は共有の形の版（`core/owned-shared.js` の `OWNED_FORMAT`。今は 4。列を狭めて送るときは外した列の数だけ下げる＝全部の列で送り直したときに `resent` で書き直される。列を足したら 1、列を足さずに形を変えたら `OWNED_ADDED_FIELDS` の数＋1 上げる）、`fileCount` は読めたファイルの数（`GlobalPalStorage.sav` も数える。`LocalData.sav` は数えない）、`missingCount` は登録してあるのに読めなかったファイルの数、`force` は登録の確定から送るときだけ `true`。GAS は `OwnedWorlds` の列 `saveKey`（`uploadedAt|stamp|hash|format|fileCount|missingCount`）に残し、応答の `result` で結果を返す（`stored` も今どおり）:
  - `new`（ワールドがない）・`newer`（届いた方が新しい）・`stale`（古い。書かない）・`unchanged`（同じセーブ・同じ識別。書かない）・`resent`（同じセーブで、同じ人の送り直しの中身がよくなった、または登録の確定〔`force`〕で悪くならない）・`same`（同じセーブの別の人・古いタブの劣った中身。書かない）。
  - どちらかに識別がない（古い画面・列を足す前・古い版の GAS が後から書いた行〔`saveKey` の先頭の `uploadedAt` がその行と違う〕）は、今までどおりセーブのファイルの更新日時で比べる（同じ時刻なら上書き）。書いたら `saveKey` は届いた値（なければ空）。
  - 応答の `world` は今公開されているワールド（`saveStamp`・`uploadedBy` を含む）。新旧の比べ方は画面と同じ関数（`web/js/core/owned-shared.js` の `compareSaves`・`decideOwnedUpload`）。手元と共有のどちらを出すか・自動登録の記録の新旧も `compareSaves` で比べる。
  - **前提: 仲間が全員同じタイムゾーン（日本時間）で遊ぶ**。保存時刻はホストの PC のローカル時刻なので、別のタイムゾーンの人がホストすると交代の前後の新旧を誤る。PC の時計のずれは、交代の間（ゲームの終了と同期の時間）より小さい前提。
- **G（`ownedSince`）**: `{ worldId, uploadedAt, presence? }` → 変わっていなければ `{ changed: false, uploadedAt, uploadedBy, saveUpdatedAt, palCount, saveStamp, presence }`、変わっていれば `owned` と同じ中身＋`changed: true`・`presence`。画面は共有の読み直しで呼ぶ（テーマ 4 の share-fetch。下の「共有されたデータは…」。`presence` は 60 秒に 1 回載せる＝下の「ページを開いている PC」）。古い GAS は `BAD_ACTION`（画面は 1 時間、今までの 2 回呼びに落とす）。
- **ページを開いている PC（`presence`）**: CacheService に、ページごとのキー `presence:<env>:<worldId>:<pageId>`（6 時間）と、ワールドの索引のキー `presence:<env>:<worldId>`（1 ワールド 50 件）。索引の更新は ScriptLock を 0.5 秒だけ試す（Web アプリの実行では DocumentLock が使えないため。取れなければ索引だけを諦め、次の送信で戻る）。値は `{ user, device, role, playing, canShare, at }`（`at` はサーバーの時刻）。キャッシュの失敗は本体の操作を失敗させない（一覧は `null`）。名前と役割は自己申告。画面から送る動きと表示は下の「ページを開いている PC」。
- **停止の印と圧縮**（巻き戻し用。GAS の編集画面から実行）: `compactOwnedTest()`・`compactOwnedProd()`（＝`compactOwned('test'|'prod')`。引数のない `compactOwned()` は何もしない）は、その環境の停止の印（Script Properties の `OWNED_PAUSED_<env>`）を立て、全ワールドを今の世代だけにし、`saveKey` の列を空にし、いちばん大きいワールドが倍になっても版 10 が書ける行数の余裕を残す。印が立っている間、新しい版の `ownedUpload`・`ownedDelete` は何も書かずに `BUSY` を返す（巻き戻しの後に遅れて届いた呼び出しが世代や `saveKey` を書き戻さないため）。`resumeOwnedTest()`・`resumeOwnedProd()` で印を消す。

#### GAS の反映（ユーザーが行う。P0 の後に本番）

1. 統合ブランチに入れた後、`npm run gas:push`（HEAD だけが変わる。本番の deployment は版 10 のまま）。

### セーブのファイルの登録（自動の読み込み）

- ブラウザ（Chrome・Edge）は `AppData` 配下のフォルダを開けないが、エクスプローラーからドロップした**ファイル**のハンドルは受け取れ、IndexedDB に保存して後から読み直せる（`web/js/save/handles.js`）。以前のセーブ連携ツール（ローカルの中継）は廃止した。
- 登録はワールドごとに 1 回（設定タブの「＋ ワールドを登録」で開くモーダル）。
  1. エクスプローラーでワールドのフォルダ（`%LOCALAPPDATA%\Pal\Saved\SaveGames\<Steam ID>\<ワールド ID>`）を開き、アドレス欄のパスを貼る。セーブのファイルにはワールド ID が入っていないため、パスから ID を取る。
  2. 画面に出る場所のファイルをドロップする（何回かに分けて足せる）。ホストのワールドは `Level.sav`・`LevelMeta.sav`・`LocalData.sav`（必須）と `Players` の中のファイル全部、任意で 1 つ上の `GlobalPalStorage.sav`。参加しただけのワールドは `LocalData.sav` だけ。
  3. ドロップするたびに読み込んで、ワールド名・ホスト名・体数をモーダルに出す（まだ保存・共有しない）。「保存」で登録し、読み込みと共有を始める。貼ったパスとドロップしたファイルが同じワールドかは機械では確かめられないので、ワールド名で確かめる。
- 登録したワールドは、一覧の「編集」でパスを入れた状態のモーダルを開き、足したいファイルをドロップして「保存」する。「削除」で登録を消す（最後の 1 つを消すと自動の読み込みも止まる）。
- 登録した後は、ゲームが保存するたび（タブが裏にあっても。下の「セーブの見張り」）と、10 秒ごとの定期の確認（前に読んでから 20 秒以上空ける。安全網）と、所持パル・継承ルート・理想個体を開いたとき・タブに戻ったときに、登録したワールドの中から最後に遊んだワールドを選び、セーブが更新されていれば読み直す（見張りの知らせと裏のタブの定期の確認では、共有された一覧は取り直さない）。別のワールドに固定するときは設定タブの「使うワールド」で選ぶ。
- 読む許可: 初めて読むとき（またはブラウザを開き直したとき）に Chrome が許可を求める。「毎回のアクセスを許可」を選ぶと、次からは確認なしで読む。**「今回のみ」で許可すると、タブがしばらく裏にある間に Chrome が許可を外すことがある**（外れるとセーブの読み直しが止まり、共有も自動登録も止まる。何分で外れるかは実機で確かめていない）ので、「毎回のアクセスを許可」を勧める。許可が要るときは、ヘッダーのセーブ連携（「許可が必要」。押すとその場で許可を求める）・所持パルの案内・設定の状態の行に、同じ文「セーブを読む許可が必要です」と止まった時刻（「14:32 から読めていません。この間に拾ったタマゴは自動登録されていない場合があります」）と「毎回のアクセスを許可」の勧めを出し、「読み込みを許可」ボタンを置く（`web/js/ui/owned-status.js` の `permissionNotice`。止まった時刻は `owned.js` の `state.auto.stoppedAt`。2026-10-15 の autoreg-visibility）。許可のないワールドがあるときは、別のワールドを黙って選ばない。許可されなかった（拒否・一部だけ）ときはトースト「許可されませんでした。Chrome のサイトの設定で許可を戻すか、ファイルを登録し直してください」。
- 読み込みが止まっているとき（許可待ち・読めない・登録なし）は、左のナビの所持パルのタブに警告の色の「!」（読み上げは「所持パル（読み込みが止まっています）」）。
- 題名とファビコン（`web/js/attention.js`。2026-10-15 の autoreg-visibility）: 題名は「画面名 · パル配合ノート」（パル詳細はパルの名前）。タブが裏にある間だけ、要確認の未読（ベルの赤い数字と同じ数え方。更新内容のお知らせは数えない）があれば題名の頭に「(3) 」、読み込みが許可待ちで止まっていれば「(!) 読み込み停止 · 」を付け、ファビコンの右上に赤い丸（1〜9・「9+」、止まっているときは「!」）を重ねる。表に戻ったら元に戻す。ファビコンは `web/favicon.svg` の 2 つの path を定数で持ち（favicon.svg を変えたら attention.js も直す）、data: の SVG にして差し替える（今の CSP の `img-src 'self' data:` で許されている）。
- 自動登録のトーストに「見る」（1 件ならその組、2 件以上なら更新日の新しい順の配合を探す）。自動登録しなかったタマゴ（照合が合わない）の通知は、押すと配合を探すでその親の組（新しく出る通知から。前に保存した通知には付かない）。
- 登録待ち（設定のワールドの行の、登録者の選択のすぐ上）: 登録されずに残っている候補を「登録待ち 3 件（登録者未設定 2・登録済みと違う 1）」で出す（0 件なら出さない。共有の結果を待っている保留の候補は数えない。下の「ホストの交代」）。「登録済みと違う」の行は親 2 体の絵・「登録を開く」（配合を探すでその組）・「破棄」（確かめてから。その候補を自動登録しない）。登録者未設定はすぐ下の登録者の選択で片づくので数だけ。**候補の子（配合表で決めた値）は出さない**（`auto-register.js` の `pendingSummary` は親と理由だけを返し、破棄に使う ID も子を含まない）。
- 読み込みで飛ばすのは、必須（`Level.sav`・`LevelMeta.sav`・`LocalData.sav`）以外の消えたファイルだけ（所持パルのタブに知らせる）。ただし、飛ばす前にまず採用を保留して読み直し、30 秒たっても同じなら飛ばす（保存の途中の置き換えで一時的に消えただけかもしれないため。下の「セーブの見張り」の「読み直しの保留」）。読めないエラー（許可・ゲームの保存中など）は失敗にし、共有もしない。必須のファイルが読めないワールドは、ホストか参加かを判定せず、共有を止める。選んでいなければ、読めるワールドのうち最後に遊んだものを読み、読めないワールドがあれば知らせる。
- 共有は、このページでホストのワールドのセーブを正常に読めたときだけ行う（開き直した直後は、保存済みのデータがあっても一度読み直す）。読み込みの途中で登録の削除を押した場合、その読み込みの結果では共有しない。
- 1 回のドロップに同じ名前のファイル（同じ場所に入るもの）が 2 つ以上あると、どれが正しいか分からないので、そのファイルはどれも受け取らない。
- 同じワールドかは、ワールド ID（フォルダ名）だけで見分ける。参加すると、自分の PC にホストのワールド ID と同じ名前のフォルダができ、`LocalData.sav` だけが書かれる。ワールドデータを仲間に渡すときにフォルダごとコピーすれば ID は変わらないので、誰がホストしても同じワールドとして扱える（前にホストしたワールドに参加すると、更新日時で参加と判定する）。フォルダ名を変えると別のワールドになる。
- 一度もホストしていないワールドに参加するときは、そのワールドの `LocalData.sav` を 1 回登録しておくと、遊んだワールドとして自動で選ばれる。
- 登録した後に仲間が増えると、その人の `Players\<ID>.sav` は登録されていない。所持パルのタブに案内が出るので、案内の「ワールドを編集」（または設定の登録したワールドの「編集」）からドロップして足す。
- パル次元ストレージの中身は、その人の `Players\<ID>_dps.sav`（次元ストレージを使い始めたときにできる）にある。登録の後に使い始めた人の `_dps.sav` は登録されていないので、同じく「ワールドを編集」からドロップして足す（登録のモーダルの「Players\ の中のファイル全部」の行にも添えてある）。2026-10-16 の sync-fixes の dps-missing で、読めていない個体を数えて知らせるようにした:
  - `Level.sav` には全員の次元ストレージの個体の一覧（`InLockerCharacterInstanceIDArray`）がある。そのうち、読めた `_dps.sav` にない個体の数を数える（`web/js/save/palworld.js` の `buildSnapshot` の `stats.inLocker`・`stats.inLockerMissing`。数だけで、個体の ID は残さない。`npm run check:save` の「次元ストレージ: Level.sav N 体・読めていない M 体」）。一覧には誰の分かが入っていないので、欠けを人に割り振れない。
  - ホストの画面（この PC で読んだセーブ）: 読めていない個体があれば、所持パルの案内・ヘッダーのセーブ連携（押す前の説明とパネルの困りごと）・理想個体の結果の上に「Level.sav ではパル次元ストレージに 118 体いますが、27 体を読めていません。Players\XXXX_dps.sav（Bob）が登録されていないかもしれません」と［ワールドを編集］を出す。候補は `Players\<ID>.sav` は読めたのに `_dps.sav` を読めていない人（Lv の分かる人だけ。次元ストレージを使っていない人も入るので「かもしれません」）で、欠けの数は候補の人数で割らない。候補がいなければ「…読めていません（ファイルが足りないか、保存の途中に読んだ可能性があります）」（ボタンなし）。数のない古い保存データでは出さない（分からない）。
  - 参加者: 候補のプレイヤーに欠けの数（`dpsGap`）を付けて共有する（players の JSON の中。列は増えない。古い GAS は黙って捨てるだけで、参加者に案内が出ないだけ）。参加者の画面では、自分のプレイヤー（「このワールドでの自分」→「プレイヤーの対応」→ 同じ名前の順。理想個体と同じ）が候補のときだけ「パル次元ストレージの 27 体が出ていません。ホストの登録にあなたの Players\XXXX_dps.sav がないかもしれません。ホストに足してもらってください」を同じ 3 か所に出す。ほかの人が候補のときは出さない。
- IndexedDB に保存できないブラウザ（シークレットウィンドウなど）では、ページを開いている間だけ使う。
- Firefox など、ドロップからハンドルを取り出せないブラウザでは、Chrome か Edge で開くよう案内する（フォルダからの手動の読み込みは 2026-10-06 に廃止した）。
- ゲームの保存の途中に読むと失敗することがある。見張りの知らせで読んだときは自動で読み直す（下の「セーブの見張り」）。定期の確認・「今すぐ読み込む」では失敗になるので、少し待ってから「今すぐ読み込む」を押す。
- 手元のセーブで読み込みを確かめるには `npm run check:save -- "<ワールドのフォルダ>"`（省略すると最後に遊んだホストのワールド）。

### セーブの見張り（2026-10-17 追加。sync-fixes の save-watch）

ゲームの保存（約 30 秒ごと）を見張り、一式を書き終えたところで読み直す。設計と P0 の実測は `docs/sync-fixes/README.md` の「P0 の結果」「P0 で決めたこと」「6. save-watch」。

- 仕組み: 見張りは Worker（`web/js/save/watch.js` の `createSaveWatcher`。`web/js/save/worker.js` の `type: 'watch'`・`'stop'`。解析の Worker とは別に 1 つ）の中で動く。画面のスレッドの `createWatchClient` が、見張る対象（`web/js/owned.js` の `watchTargets()`）を世代番号と組で送り、違う世代の知らせは捨てる。
  - 対象: 登録したワールドのうち、直近の一覧で許可があったもの（保存の途中などで一時的に読めないワールドも外さない。外すと戻ったことに Worker が気づけない）。「使うワールド」を選んでいればそのワールドだけ。今のワールド（連携しているワールド、なければ最後に遊んだワールド）は登録した全ファイル、ほかのワールドは `Level.sav`・`LocalData.sav` だけを 5 秒ごとの確認で（最後に遊んだワールドが替わったことに気づくため。数秒遅れても困らないので Observer は使わず、Chrome が押さえるフォルダを今のワールドの 1 つにする）。同じ対象（ワールド・パス・登録の版・今のワールドか）なら送り直さない。自動の読み込みが無効・対象がなければ Worker を止める。
  - **FileSystemObserver で見張るのは、今のワールドのフォルダの直下のファイル（`Level.sav`・`LevelMeta.sav`・`LocalData.sav`）だけ**。`Players` の中（`<ID>.sav`・`<ID>_dps.sav`）と `GlobalPalStorage.sav` は Observer に渡さず、Worker の 5 秒ごとの `getFile()` の確認だけで拾う。理由: Chrome は見張っているファイルの入ったフォルダを押さえる（ファイルが消えた後も 0.5〜2 秒）ので、`Players` の中を見張っていると、SaveSync が同期を受け取るときに `Players` を消せずに止まり、ワールドのフォルダが `LocalData.sav` だけになる（2026-10-17 に実際に起き、作業用のフォルダで再現した）。直下のフォルダは `LocalData.sav` が残るので SaveSync に消されない。`getFile()` と中身の読み込みはフォルダを押さえない。画面側（`watchTargets()` が Observer に渡す印 `observe` を直下のファイルだけに付ける）と Worker 側（`observable(path)` で絞る）の 2 か所で守り、`Players`・`GlobalPalStorage.sav` のハンドルが `observe()` に渡らないことをテスト（`test/save/watch.test.js`・`test/web/owned-store.test.js`）で確かめている。**`Players` の中を Observer で見張る変更はしない**。
  - 方式: Observer が使えれば Observer（ワールドごとに 1 つ。どのファイルの通知かは `root` の名前で見分ける）。ゲームはファイルを置き換えて保存するので、保存のたびに `disappeared`・`errored`（まれに `appeared`）が来る（P0）。そのたびに変化として数え、`getFile()` が通ってから `observe()` し直し（10・50・250・1000 ms の段）、直後に照らし合わせる。4 段で張り直せないファイル（と、始めたときにファイルがなく見張れなかったファイル）は 5 秒の確認だけにし、5 秒ごとの確認でファイルが戻ったのに気づいたら張り直す（SaveSync の同期の受け取りでファイルが消えても、読み込み直さずに戻る。消えている・読めない間は張り直しを試さない。Observer に渡すのは上の直下のファイルだけのまま）。`appeared`・`modified`・`moved` はそのファイル、`unknown` はそのワールドの全ファイルを照らし合わせる。5 秒ごとの確認は Observer があっても動き、全部のファイル（`Players` も）を更新日時・大きさで比べる（前の回が終わっていなければ飛ばす。Worker の中のタイマーは裏のタブでも 5 秒のまま。P0）。Worker を作れないブラウザは、`app.js` の 10 秒ごとの定期の確認（セーブは 20 秒以上空ける。タブが長く裏にあると Chrome が 1 分に 1 回まで遅らせる）だけ。
  - 一式の書き終わり: ワールドごとに、最後の変化から 1 秒（`quietMs`）静かになったら、または最初の変化から 10 秒（`maxWaitMs`）で、全ファイルを照らし合わせ、前に知らせたときから変わったファイルを画面に知らせる（`settled`）。ホストのワールド（`Level.sav` を登録したワールド）は、`Level.sav` の変化を見るまで 1 秒を数えない（`LocalData.sav` は `Level.sav` より最大 2.74 秒早く書かれ、`Level.sav` から後は数 ms でそろう。P0）。画面は `owned.refreshFromWatch(worldId)` で読み直す（共有は読み直さない。読み込み中・順番待ちなら、終わった後に 1 回だけ）。許可が外れた（`NotAllowedError`）ことも 1 回だけ知らせ、読み直しが許可待ちにする。
- 読み直しの保留（見張りの知らせでも、ページを開いた直後の最初の読み込みでも、定期の確認でも同じ。`owned.js` の `readAuto` が `'held'` を返す）: 読んだ一式を採用せず、前の手元のデータ・表示・共有（取り消した共有の予約・再試行も今のセーブのまま戻す）を残したまま読み直す。
  - 読む前と後でファイルの印（更新日時・大きさ）が違う（保存の途中に読んだ。P0 で 1 回、`Level.sav` と `LevelMeta.sav` が 30 秒食い違った）: 1 秒後。
  - 登録したファイルの読み・解凍・解析の失敗と一時的な消失（所持パルの案内の「〜を読めませんでした」になるもの）: 最初に見た時刻から 1・3・10・30 秒。30 秒たっても同じ形（パスと理由の集合）なら、壊れた・消えたとみなして今までどおり飛ばして読み、案内を出して共有する（新しいセーブなら欠けたまま `newer` で載り、後でファイルが戻れば `missingCount` が減って `resent` で直る）。受け入れた形はワールドごとにページの中だけ覚え、同じ形なら次から待たない（消したままのファイルで毎回 30 秒遅れない）。全部読めたら忘れ、形が変われば待ち直す。登録の確定（登録のモーダルで読んだ結果）はすぐ採用する。
  - 見張りから読んだときの読めない失敗（ゲームの保存中〔`NOT_READABLE`〕・必須のファイルの一時的な消失・`Level.sav` を読めない／解析できない）: エラーを出さず、別のワールドに替えたり止めたりせずに、最初の失敗から 1・3・10 秒で読み直す。3 回目もだめなら今までどおりの扱い（エラーの案内）。
  - 読み直しのタイマーは 1 本。別のワールドに替わった・登録を消した・採用できたら止める。
  - 「今すぐ読み込む」（ヘッダーのセーブ連携のパネル・設定）で保留になったときは、トースト「セーブの一部をまだ読めないため、少し待ってから自動で読み直します」（`ui/owned-status.js` の `refreshNow`。何も起きないように見えないように）。
- 確かめ方: ヘッダーのセーブ連携のパネルの「監視」の行（自動の読み込みが有効で登録があるときだけ）。「ファイルの変更」（Observer）・「5 秒ごとの確認」（Worker の確認だけ）・「定期の確認（タブが裏だと 1 分ごと）」（Worker を作れない）と、今のワールドの「最後の保存 12:03:30（7 ファイル・0.8 秒）」（書き終えた時刻〔変わったファイルの更新日時の最大〕・変わったファイルの数・書き始めから書き終わりまで）。
- 見ていないこと（実機で確かめる）: Edge、受け取る側の PC で SaveSync が直下のフォルダそのものを作り直すことがあるか、ゲームでワールドを削除するときに直下のファイルの見張りが邪魔をしないか。

### ホストの交代（SaveSync）（2026-10-17 追加。sync-fixes の host-rotation）

ホストは仲間内で交代する。ゲームを終えると SaveSync（Steam）が、ワールドのフォルダ全体を全員の PC に同期する。設計と実測は `docs/sync-fixes/README.md` の 7 と「P0 の結果」。

- **全員が一式を登録しておく**: 交代でホストする人も、`Level.sav`・`LevelMeta.sav`・`LocalData.sav`・`Players` のファイルを登録しておく（登録のモーダルの組の見出しは「ホストする PC（交代でホストする人も）」。参加者として登録したワールドの行と、参加者として登録するときの結果欄にも、［編集］で足すよう出す）。`LocalData.sav` だけの登録のままホストすると、その PC のページはセーブを読めず、共有も配合牧場の自動登録も動かない（参加者の画面に下の「共有が止まっています」が出る）。
- **役割の判定**: 今までどおり `judgeRole`（上の「設定」の節）。同期を受け取った PC は、全ファイルの更新日時が元の最後の保存の時刻にそろうので、ゲームをしていなくてもホストと判定される。そこで「ゲーム中」を別に推定する。
- **ゲーム中の推定**（`web/js/core/playing.js`。`owned.js` の `state.play`）: 変化の値は、ホストは `Level.sav` の中の保存時刻（登録したファイルから読んだセーブ。登録の確定で読んだものも）、参加者は `LocalData.sav` の更新日時（一覧の `playedAt`。参加者と判定するのは `LocalData.sav` の方が新しいときなので同じ値）。読むたびに値を記録し、見た時刻が直近 2 分の中にある変化のうち、続く 2 回で後の変化の間（値の差）が 20〜90 秒のものがあれば「ゲーム中」（ゲームは約 30 秒ごとに保存する）。
  - 間を見た時刻ではなく値の差で測るので、裏のタブで確認が遅れても、同期で更新日時が元の時刻に戻されても（値が過去に動く）だまされない。受け取る側の PC の同期の書き込みは 1 回の変化なので、続けて 2 回の条件で除ける。
  - ページを開いた直後の最初の読み込みは基準だけ（数えない）。ワールドか役割が変わったとき、見張りの対象が変わったとき（見張りのやり直し。見張っていなかったところから始めるときは除く）は数え直す。2 分変化がなければ外れる。使うのは、今のワールドと役割が記録と同じときだけ。
  - ヘッダーのセーブ連携のパネルの「ゲーム」の行: ホストは「ホスト中（推定）」か「ホスト用のセーブあり（ゲームの保存は続けて見えていません）」（同期で受け取った・ゲームを終えた後）、参加者はゲーム中のときだけ「参加中（推定）」。
- **セーブの識別と共有の結果**: 上の「共有の世代とセーブの識別」（`Level.sav` の中の保存時刻で同じセーブかを見分ける。結果は `new`・`newer`・`stale`・`unchanged`・`resent`・`same`）。同期の後にゲームをしていない PC のページが送っても、同じセーブは `unchanged`（自分が前に送った）か `same`（別の人が送った）になり、書かない（`uploadedBy` も変わらない）。共有より新しいセーブ（ホストの PC でページを開き忘れて遊んだ分）は `newer` で載る。
- **配合牧場の自動登録**（`web/js/auto-register.js`）: 証拠を集めることと、登録してよいと決めることを分けた。
  - 新しいタマゴの証拠は、今までどおりセーブを読むたびに集め（タマゴの証拠はそのセーブにしかないので、共有の結果を待たない）、「配合のキー＋そのセーブの中の保存時刻（`saveStamp`）」の候補として端末の記録（`<namespace>.autoBreeding.farms.<env>.<ワールド ID>` の `pending`）に残す。候補は `stamp`・`savedAt`・`seenAt`（読んだ日時）・`playing`（読んだときホスト中〔推定〕だったか）・`state`（`hold` 保留／`ok` 登録してよい）を持つ。保存時刻の読めないセーブの候補と、前の版の候補（`stamp`・`state` がない）は `ok`（今までどおり）。ファイルの更新日時だけが新しい同じセーブ（同期で書き換わった）では候補を増やさない。
  - 共有の結果（`owned.js` の `state.upload`。送ったときの環境〔`scope`〕が今の環境と同じものだけ。環境を切り替えた後に残っている前の環境の結果は使わない）が届くたびに、判定 `{ kind, stamp }` を同じ記録の `verdicts`（直近 20 件。同じ判定は 1 回）に足し、その stamp（S）以前の保留の候補を決める（S より後に読んだ候補は、その判定では決めない）。結果が読み込み中に届いても記録し、後で読んだ候補・読み込み直しの後のページにも当てる。識別のないセーブ（stamp が空）の結果は、自分の共有が載ったとき（mine）だけ `{ kind: 'mine', stamp: '', savedAt }` とし、候補の更新日時が送ったセーブの更新日時以前なら登録してよいにする（same・stale は同じセーブかを見分けられないので何もしない。更新日時は同期で書き換わるので、同じセーブの判定には使わない）。記録を書くときは、書く直前の最新の記録の判定と和を取り、書く候補に当て直す（別のタブが同時に判定を足しても消えず、捨てた候補が戻らない）。

    | 共有の結果（`state.upload.status`） | 判定 | 候補 |
    |---|---|---|
    | `done`（自分の共有が載った: `new`・`newer`・`resent`・自分の前の送信が届いていた `unchanged`・古い GAS の `stored`） | mine | S 以前 → 登録してよい |
    | `same`（別の人が同じセーブを共有済み: `same`・他人の `unchanged`） | same | stamp が S の候補 → 捨てる（そのセーブは別の PC の担当）。S より前は保留のまま。公開しているのが送ったときの自分の ID（同じ PC の別のタブ）なら mine |
    | `stale`（別の人が新しいセーブを共有済み） | stale | ホスト中（推定）の間に読んだ候補 → 登録してよい（自分のプレイの証拠）。それ以外は保留のまま（推定が立たなかっただけで、同期で受け取ったとは言い切れない） |
    | `sending`・`error`・なし | — | 保留のまま |

  - 一度登録してよいになった候補は、後の判定で取り消さない（プレイヤーの対応が未設定で待つ候補も消さない）。保留のまま 7 日たった候補は捨てる（読んだ日時から。セーブを読むときと判定のときに）。登録は、登録してよい候補だけを配合のキーごとに証拠をまとめて今までの流れ（登録者の判定・登録済みとの食い違い・通知）で行い、登録したらそのキーの候補（別のセーブの保留の分も）を全部外す。設定の「登録待ち」は登録してよい候補だけを数える。
  - こうなる: 応答を失った S1 の証拠も、後の S2 が自分の共有として載れば登録される。別の人が新しいセーブを載せても、自分の S1 の候補は捨てない（後で自分の共有が載れば登録される）。同期で受け取った同じセーブ（別の人が載せた）の証拠は捨てる。古い GAS（本番の版 10）は stamp を返さないが、`stored` を自分の共有として扱うので今までどおり登録する（同期で受け取ったセーブとは見分けられない）。
  - 前の版のまま開いているタブは、保留の候補も今までどおり登録し、記録を書き戻すときに `stamp`・`state`・`verdicts` を落とす（落ちた候補は、この版では登録してよいとして読む）。配信の後は、開いているタブを読み込み直す。
- **参加者の「共有が止まっています」**（`web/js/ui/owned-status.js` の `shareLagNotice`）: 参加者がゲーム中（推定）なのに、共有のセーブ（`saveUpdatedAt`）が 5 分以上古い、またはこのワールドの共有がないとき、所持パルの案内（［ワールドを編集］のボタンつき）とヘッダーのチップ（警告の色・「共有が止まっています」。押す前の説明とパネルの困りごとに同じ文）に「ゲーム中のようですが、共有は 12 分前のセーブのままです。今のホストの PC でこのページが開いているか確かめてください（あなたがホストなら［ワールドを編集］で Level.sav・LevelMeta.sav・Players のファイルを足してください）。」（共有がなければ「…このワールドはまだ共有されていません。…」）。共有を 60 秒より前にしか確かめていないとき（裏のタブから表に戻った直後など。参加者のタブは裏では共有を読まない）・確かめたのが今のワールドでないとき（`state.shared.fetchedWorldId`。取得に成功したときに入れる）・共有の取得に失敗しているときは出さない。

### ページを開いている PC（2026-10-17 追加。sync-fixes の page-presence）

どの PC でこのページが開いているかを仲間どうしで見られるようにした（今ホストしている人の PC でページが閉じていると、共有も配合牧場の自動登録も止まるため）。GAS の側は上の「共有の世代とセーブの識別」の `presence`（CacheService。シートには書かない）。設計は `docs/sync-fixes/README.md` の 8。

- **送る**（`web/js/owned.js` の `reportPresence` と、共有の読み直しの `ownedSince`）: ログインしているページは、今のワールド（表示しているワールド）について 60 秒に 1 回送る。表のタブは 10 秒ごとの共有の読み直し（`ownedSince`）に載せて別には送らない。載せる回がないとき（一覧だけを読む 5 分ごとの回・まだ共有されていないワールド）と裏のタブ（共有を読まない）は、`app.js` の 10 秒ごとのタイマーで、読み直しの後に `presence` を別に送る。
  - 裏のタブはタイマーが 1 分ごとまで遅れるので、送る間隔も広がる（表示は 3 分の幅で見る）。タイマーが少し早く来ても 5 秒の余裕の中なら送る。タブが freeze されると送れない（表示は「最近の応答なし」になる）。
  - ワールド・送る値（役割・ゲーム中・共有できる）が変わったら、間隔によらず次の回（10 秒以内）に送る。ログインしていない・ワールドがないときは送らない。
- **値**: `role`（このページの判定の結果。`host`・`guest`、連携していないワールドは `none`）・`playing`（ゲーム中の推定。上の「ホストの交代」）・`canShare`（このワールドをホストの一式〔`Level.sav`・`LevelMeta.sav`・`LocalData.sav`〕で登録していて、直近の確認で読む許可がある。一覧の確認の後の読み込みで許可が外れ、自動の読み込みが許可待ちで止まっている間も false）・`user`（ログイン中の ID）・`device`（PC の ID。ワールドごとのランダムな値を localStorage の `<namespace>.owned.device.<ワールド ID>` に残す）・`pageId`（ページを読み込むたびにメモリの中で作るランダムな値。sessionStorage は複製したタブで同じ値になるので使わない）。
  - **ID は認証にも本人の証明にも使わない**（共通パスワードの認証なので、名前と役割は自己申告。だれでも別の名前で送れる）。ワールドごとに別の値なので、ワールドをまたいで同じ PC だとは分からない。
- **古い GAS**（本番の版 10）: `ownedSince`・`presence` が `BAD_ACTION` なら、接続先と環境ごとに 1 時間は送らない（`ownedSince` と同じ覚え方。`ownedSince` の `BAD_ACTION` でも覚える）。そのとき前に受け取った一覧も消す（GAS を版 10 に戻した後に、前の一覧が 6 時間出続けない）。送れなくても（通信・`BAD_ACTION`）共有とセーブの読み込みは失敗にしない（次は 60 秒後）。応答の一覧が `null`（サーバーのキャッシュを読めなかった）なら前の一覧のまま。
- **表示**（ヘッダーのセーブ連携のパネルの「ページを開いている PC」の行。1 台 1 行。`web/js/ui/owned-status.js` の `openPages`・`openPagesLines`）: 受け取った一覧（`ownedSince`・`presence` の応答。表のタブは 10 秒ごと）を PC（`device`）ごとにまとめる。
  - ●（3 分以内に応答があった PC）: 「Alice · 1 分前 · ホスト中 · 共有できる」。役割（ホスト中・ホスト用のセーブあり・参加中・参加者・セーブ未連携）と共有できるは、その PC の 3 分以内のページの応答だけでまとめる（1 台で複数のタブが開いていれば、ホスト → 参加者 → 未連携の順に選び、ゲーム中はその役割のタブのどれか、共有できるはどのタブか 1 つでも）。
  - ○（それより前）: 「Bob · 最近の応答なし（3 時間前）」。閉じたとは限らない（裏のタブで遅れた・キャッシュが消えた）ので、古いページの役割は出さない。6 時間より前は出さない。
  - 同じ人（ID をそろえて比べる）の 2 台目からは「Alice（PC 2）」（番号は今の一覧〔6 時間以内〕に残る PC の ID の順で、見る人によって入れ替わらない。ID の順で先の古い PC が一覧から消えると繰り上がることがある）。この PC は「（この PC）」。経過はサーバーの時刻で測る（応答のサーバーの時刻＋受け取ってから経った時間。PC の時計がずれていても 3 分の境目がずれない）。
  - 一覧が分からない（古い GAS・まだ受け取っていない・別のワールドの一覧）・6 時間以内の応答がなければ行を出さない。
- **CacheService は期限（6 時間）の前に消えることがある**。消えると、開いているページも次の送信（1 分以内）まで一覧から消えるか「最近の応答なし」に見える（索引の鍵〔ScriptLock を 0.5 秒〕が取れなかったときも同じで、次の送信で戻る）。
- 確かめ方: 2 つのブラウザ（か PC）で同じワールドを開き、パネルに両方が ● で出る。片方を閉じると約 3〜4 分で ○「最近の応答なし」になる。本番が版 10 の間は行が出ない（版 11 の後）。

- パネルの下の行（結果の行。薄い色の地の帯）に「N / M 体 · ♂a ♀b タマゴ c」（N を太く）、効いている条件のチップ（枠つきのタグ。× でその条件だけを外す。入りきらない分は「+n」で、押すと隠れたチップを出し、そこでも外せる）、「すべて解除」（並べ替えは残す）、並べ替え（見出しつき）を出す（前は「すべて解除」の右に今の条件の URL を写す「リンクをコピー」があったが、2026-10-14 のユーザーの指示〈README の D31〉で機能ごとなくした。下の URL の条件で開く受け口は、理想個体の所持の状況のリンクなどが使うので残す）。パルを選んでいればパルの見出しの行の右に「理想個体 →」、パッシブを選んでいればパッシブの見出しの行の右に「継承ルート →」を出す。0 件のときは一覧に「条件をすべて解除」。条件を変えたとき、一覧の先頭がパネルの下に隠れていれば一覧の先頭へ移る。
- URL の `holder`（`mine`＝自分・`player:<uid>`。無ければ「すべて」）・`place`（カンマ区切り）・`base`（前の版。場所を拠点とタマゴにする）・`el`・`pal`・`p`・`pm`・`q`・`sort`・`dir`・`stars`・`hp`・`at`・`df` で条件を指定して開ける（どれかがあれば URL が条件のすべてを決める。並べ替えは `sort`〔と向きの `dir`。`asc`／`desc`〕があるときだけ。前の版の `sort=talent-low` は個体値の合計の低い順に読み替える）。前の版のリンク（`holder=base:…`・`holder=global`・`place=egg` など）と、前の版が保存した条件（タマゴ・グローバルボックスのチェック）も読み替える。
- キーワードは、パル名（日本語・英名・内部名）・ニックネーム・属性・パートナースキル・覚えているアクティブスキル・パッシブ（それぞれ名前と説明文）・性別（オス／メス）・タマゴ／ラッキー／アルファ・所持者・場所・預けた人（拠点の個体だけ）から探す（`web/js/core/owned.js` の `keywordFields`）。レベル・★・個体値は専用の絞り込みがあるので探さない（パッシブの説明の「+30%」などの数値は探す）。
  - 説明文も常に探すので、例えば「闇」で、闇属性のパルに加えて、パートナースキルの説明に「闇属性」が出てくるパルも出る（2026-10-10 のユーザー指示）。
  - 空白（全角も）で区切ると、すべての語を含む個体に絞る。ひらがなとカタカナ・全角と半角・大文字と小文字の違いはそろえる。
  - 一致した理由を、行の下の段に必ず出す（`keywordNotes`）。語の順に、その語が当たった項目をすべて「属性：闇」「パル名：アヌビス」「パッシブ：職人気質（作業速度 +50%）・希少」の形で（項目はパル名・ニックネーム・属性・性別・特徴〈タマゴ・ラッキー・アルファ〉・パッシブ・パートナースキル・アクティブスキル・所持者・場所・預けた人・目標の印。一覧に出ている項目でも出す）。説明文で一致したときは名前の後ろに説明文を添える。行には項目ごとに 4 つまで並べ（短い項目は縮めず、長い項目を省略）、残りは「ほか N 件」。全文は段の title。前は一覧に出していないスキルと説明だけで、属性などで一致したときは何も出さなかった（2026-10-14 のユーザーのフィードバック。README の D29）。
  - スキルの名前と説明文はゲーム本体から取り出したもの（`web/data/skills.js`）。ゲームの更新で作り直すときは `npm run extract:skills -- "<Palworld のインストール先>"`。名前の表にないアクティブスキルは ID のまま出す。
  - 説明文の中の、パートナースキルのレベル（パル濃縮）で変わる数値は「○」にしている（ゲームは別のデータから計算して出す）。レベルで変わる追記（「ダメージ増加：小」など）は入れていない。パッシブの説明は PalCalc のデータ（`web/data/passives.js` の `desc`）。
  - アクティブスキルは、スキルを読むようにした版でセーブを読み込み直すまで出ない（登録したファイルは、ページを開き直すと一度読み直す）。参加している人には、ホストの画面が新しい版で共有し直した後に出る。
- パッシブの見た目はゲームのパル詳細画面に合わせる。ランクの矢印と背景の三角模様はゲーム本体から取り出した画像（`web/img/passive/`）、左の帯・枠・板の色はゲーム画面から測った値を CSS で描く（ランク 1・2 は白、3 は金、4 は水色、マイナスは赤。ランク 5 は見本がないため推定）。ゲームの更新で画像を作り直すときは `npm run extract:passive-icons -- "<Palworld のインストール先>"`。
- 一覧は、設定タブの「データ」の「書き出し」カードの「所持パルの CSV（表示中のワールド）」で、表示しているワールドの所持パルを Excel 用の CSV（UTF-8・BOM 付き）に出せる（データがなければ押せない）。2026-10-15 の settings で、前のワールドの行の「CSV で保存」とカードの「所持パルを CSV で保存」を 1 か所にまとめた（判断事項 11）。列は `web/js/core/owned.js` の `OWNED_COLUMNS`。
- パッシブ名のマスターを更新するには `npm run build:passives`（取得元のコミットは `scripts/sources.mjs` の PalCalc と同じ）。

### 理想個体

- 目標の一覧の詳細（2026-10-15。goals-detail）: 見出しの「目標（5 · 完成 2）」とダイアログの題名「目標（5 件 · 完成 2）」（完成の数は表示しているワールドで完成済みの目標。自分のプレイヤー・所持パルが分からない〔未確認〕ときは出さない）。並びは未完成（まだ作るもの）が上、完成済みは下に薄く（それぞれ保存の新しい順）。行は 36px の絵と目標の名前（1 回だけ）・状態のピル（未完成・完成済み・未確認）。未完成の行には、自分の個体のうちいちばん近い 1 体との差「パッシブ 3/4 · 攻撃あと 8」（欲しいパッシブを持つ数 → 足りない個体値の合計の少ない順で選ぶ。届いていれば「個体値は届いています」、「欲しいものだけ」の余計なパッシブ、同じ種族がいなければ「未所持」）と「（孵化待ちに n 個）」。完成済みは状態を押すと所持パルをその目標の種族・パッシブ・タマゴ以外の全部の場所（グローバルパルボックスを含む）で開く。完成の通知の行き先も同じ所持パル（通知の id と本文は変えていないので既読はそのまま）。
- 目標の一覧の「手術で完成できる」（2026-10-16。implants）: 完成品がなく、自分の個体に、個体値の目標を満たし足りないパッシブ（1 個以上）がすべてパル手術台で付けられる個体（「欲しいものだけ」は余計なパッシブが足りない数以下）がいれば、状態のピル「手術で完成できる」（完成済みと未完成の間の色）と「アヌビス♂ Lv52（拠点 1）＋神速（使い切りインプラント：神速・在庫 4） · ほか n 体」（付けるものの少ない個体 → Lv の高い個体を先に。在庫はホストの画面だけ）。判定は手術台の表だけで在庫は見ない。完成の通知（ベル）は鳴らさない（完成の判定 `goalMatches` は今までどおり。手術をしてセーブに入ったら完成として知らせる）。
- 目標（2026-10-15。goals-merge。D5）: 前のウィッシュリストは理想個体の「目標」にまとめた（タブは 5 本）。パル詳細の「☆ 目標に保存」と、配合を探すで子だけを選んで 0 件のときの「☆ 目標に保存（作れるようになったら知らせます）」で、その種族を「種族だけの目標」（パッシブなし・個体値の条件なし。一覧のタグは「パルだけ」）にできる（もう一度押すと外す）。目標の一覧（見出しの「目標（N）」のダイアログ）の行に、完成の状態・「配合: 登録済み n 件 →」（押すと配合を探す）・所持パルがあれば「所持 n 体（親になれる m）」。前の `#/wishlist` は `#/ideal?goals=1`（目標のダイアログを開く）に読み替える。理想個体のタブには、表示しているワールドで完成した目標の数「完成 n」（0 なら出さない）。
- 配合の登録の観測と通知: 目標の種族ごとに、確定した登録（送信待ちを含まない）で「作れる」かを、前に見たサーバ時刻より新しいデータのときだけ判定する（起動時のキャッシュ・名前の変更中は判定しない）。目標を足した時点で作れても知らせず、作れるようになったら「〈パル〉の配合が登録されました」（本文「A＋B で作れます（ほか N 組）」）、作れる間に組が増えたら「〈パル〉の配合が増えました」、作れなくなったら消える。通知は「種族だけの目標」がある種族だけ（パッシブつきの目標の種族は観測だけ）。id は前のウィッシュリストと同じ形（`wishlist:<env>:<palId>:<時刻>`）なので、既読は引き継がれる。観測は前の版のタブが書き換えない別のキー `<namespace>.goalsObs.<env>.<userIdKey>`（目標のキーの形は変えていない。`web/js/core/goal-observations.js`・`web/js/ideals.js`）。名前の変更で移す。
- 前のウィッシュリストの移行（`web/js/goals-migration.js`）: ログインした環境・ID ごとに 1 回（と、旧キーが別のタブで書き換わったとき）、旧キー `<namespace>.wishlist.<env>.<userIdKey>` を種族だけの目標（id `wish-<palId>`。同じ条件の目標があればそれに併せる）と観測へ移す。目標を書いて読み戻し、観測と移行の記録を書いて読み戻してから旧キーを消す（途中で失敗したら旧キーを残し、次の起動で続きから同じ結果）。目標が 100 件の上限なら残りは「未移行」で、一覧に「ウィッシュリストの n 件をまだ目標に移せていません」と「旧ウィッシュリストを見る」（読み取り専用）。移した目標を外した後に、前の版のタブが旧キーへ書き戻しても作り直さない。

- 「理想個体」タブでは、目標のパル・欲しいパッシブ・個体値の目標（HP・攻撃・防御。チェックを外すか空欄で条件なし。保存は 0）・ケーキを選ぶと、表示しているワールドの所持パルから、配合牧場に置く ♂×♀ の組を上から並べる（下の「配合の計画」）。
- 候補は、目標と同じ種族どうしと、登録済みの配合（子が目標のもの）の親。タマゴ（孵化するまで牧場に置けない）・グローバルパルボックス・人間・性別不明の個体は使わない（切り替えはない。`web/js/core/ideal.js` の `isParentCandidate`）。産まれたタマゴは、孵化させて受け取ると候補に入る。欲しいパッシブの選択欄の所持数も、タマゴとグローバルパルボックスの個体を数えない。
- 一覧は「配合の計画」: 理想個体を作るのにおすすめの組を、配合牧場に上から置く順に、別々の個体で最大 20 組並べる（上の組に使った個体は下の組に使わない。牧場が 3 つなら上から 3 組を置く）。並べ方の切り替えはない。組は目的で 3 つに分け、この順に並べる（`web/js/core/ideal.js` の `idealPlan`・`comparePlan`。2026-10-08 のユーザー指示）。
  - 「完全体作成組」: 欲しいパッシブと個体値の目標を全部満たす子（完全体）を作れる組。2 体で欲しいパッシブがそろい、条件のある各ステータスに目標以上（キノコケーキでは目標−5 以上）の親がいて 1 個のタマゴの成功率が 0 でない組（1 回で作れる。異種の登録済み配合を含む）と、同じ種族どうしで両親とも欲しいパッシブを全部持つ（5 個以上は除く）組（子を入れ替えながら作る）。完成までのタマゴの平均（`eggs`）の少ない順。`eggs` は、世代の平均が出る組では世代の平均（この 2 体のまま続ける場合も含めて最適に選ぶので 1 / 成功率 以下）、出ない組では 1 / 成功率。
    - 世代の平均は `generationTable`（両親それぞれの「ステータスが目標に届くか」の 3 ビット・余計なパッシブの数・共有している余計なパッシブの数を状態にした確率最短路をダイクストラ法で解く。ケーキなし・スペシャルケーキでは厳密。キノコケーキ・豪華野菜ケーキは目標−6 以上を届く扱いにした目安で並べ、目標−1 以上だけを届く扱いにした上限も求める。画面には出さない）。
  - 「パッシブ厳選組」: 欲しいパッシブを全部、候補のだれかが持っているときに、個体値は見ずに、欲しいパッシブを 1 体に集める組（2 体で、どちらか 1 体より多くの欲しいパッシブがそろう組。3 体以上に分かれていれば、途中まで集める組も含む）。集まる数の多い順 → 全部継ぐ確率（パッシブの条件は「全部持つ」で計算）の高い順。
  - 「個体値厳選組」: それ以外の組。欲しいパッシブを候補のだれも持たない（配合では作れない。ダイヤモンドのパッシブなど）ときは、全部この組になり、画面に「〇〇 を持つ親の候補がいません。いまは個体値厳選組だけを出しています。」と、パッシブごとのパル手術台の案内（下の「パル手術台」。2026-10-16 の implants で、前の「別に手に入れてください」の扱いから変えた）と、そのパッシブを運ぶ継承ルートへの案内を出す。パッシブは後から手に入れる前提で見ずに、個体値の目標がそろう子が産まれるまでの平均（`talentEggs`。同じ種族なら、パッシブを見ない世代の表で子を入れ替えながら）の少ない順。
  - どの組も、同じ組み合わせで別の子も登録されている組は後ろに回し、最後は個体 ID で決める（同じ入力なら必ず同じ並び）。
  - パッシブの条件を満たす子が産まれない組（スペシャルケーキで 4 個未満の「欲しいものだけ」なら全部、パッシブを持つ親で「パッシブなし」）は置いても完成しないので出さない（`blocked`）。
  - 別々の個体は、並びの上から順に、まだ使っていない個体どうしの組を選ぶ（貪欲法。組の数を最大にする割り当てではない）。全部の組を並べ替えずに済むよう、♂ ごとに良い組を 2×20 件だけ残してから選ぶ（i 番目に選ばれる組は、その ♂ の組のうち使われた ♀〈i−1 体以下〉の組を除いた一番良い組なので、必ず残っている）。♂ の上位が上の目的の組で埋まっていれば、その ♂ の個体値厳選組の平均は求めない。キノコケーキの「平均の上限」は選んだ組にだけ求める。
  - 組のカードは [番号][札] の 1 行と ♂♀ の 2 行だけ（登録の注意があれば下に 1 行）。完成までの平均などの数値・内訳の文（「子と入れ替えながら · 1 個のタマゴで X%」など）・組の出どころ（「同じ種族どうし」「登録済みの配合 A♂ × B♀」）・余計なパッシブの確率の注記は、2026-10-14 のユーザーのフィードバック（README の D30）でなくした（並びの計算は変えていない）。組の札（組の目的〈アイコンつき〉・変更あり・配置中・交換先の牧場・持ち主）は押すと説明が開く（`web/js/ui/hint.js`。固定配置で周りを動かさない）。
  - 個体値厳選組が続き、見込み（世代の平均、なければ 1 個のタマゴの確率）が前の組と同じ組は「同じ見込みの組 ほか n 組」に畳む（候補のだれも届かないステータスがあれば、その理由も出す）。並びの先頭と、配合牧場の判定が指している組は畳まない。番号は振り直さない。開閉はタブを切り替えても残る。
