## 動作確認

- 画面をローカルで確認するには、`npm run dev` を実行してから `http://localhost:5173/?mock=1` を開く。架空データを入れるなら `&seed=30` を付ける。
  - モックはメモリ上だけで動くので、再読み込みで初期状態に戻る。
  - 最初に入力したパスワードをそのセッションの共通値として使う。新規登録してログインする。`seed` を指定した場合は ID `架空データ` でもログインできる。
- 本番の API を確かめるには `node scripts/smoke.mjs` を実行する。認証の確認だけで、読み取りのみ。
- 書き込みまで確かめるには `node scripts/api-check.mjs` を実行する。
  - テスト用シートに対して、登録・冪等性・重複・競合・+1・編集・削除と復元・統合・並列 5 件の書き込みを確かめる。
  - 開始時に、テスト用シートの有効レコードを片付ける。
  - 応答の環境が本番だった場合は、その時点で中断する。

## 権限の再承認

GAS に新しい権限（OAuth スコープ）が必要な変更を入れたら、スクリプトエディタで関数を 1 回実行して承認し直す。
承認するまで、匿名の利用者全員がエラーになる。

## 共通パスワードと ID

- 更新後、所有者が Apps Script エディタで `setup()` を再実行する。`設定`・`Users`・`Users_test` シートと保護されたヘッダーを追加する。既存の配合データと設定値は変えない。
- 本番の共通パスワードは `設定` シートの `項目` が `共通パスワード` の行の `値` に保存する。初回は旧 Script Property `PASSCODE` を移行し、旧プロパティを削除する。旧値がなければ自動生成する。値はログに出さない。
- 変更するときは、そのセルを直接書き換えて利用者に新しい共通パスワードを伝える。値の列は書式なしテキスト（`@`）を保つ。数字だけの値も文字として入力する。
- 照合は前後の空白を除いた完全一致で、大文字小文字・記号・日本語を区別する。設定が空、シートや行がない、テスト値が空、両者が同じ場合は全リクエストを拒否する。
- `Users` は本番の ID 一覧、`Users_test` はテストの ID 一覧。列は `userId` / `createdAt`。利用者は画面の新規登録から ID を追加する。ID は制御文字と前後の空白を除いた1〜20文字で、全角英数や大文字小文字が違っても同じ ID とみなす。
- ID の確認・削除は該当する Users シートで行う。削除した ID の端末は次のデータ取得時にログアウトする。配合レコードの登録者名や既存レコードは変わらない。
- 利用者は設定画面の「名前を変更」で自分の ID を変えられる（API の `rename`）。Users の行と、配合レコードの登録者名（削除済みを含み、全角英数や大文字小文字の違いも同じ名前とみなす）、OwnedWorlds の `uploadedBy` を新しい名前にそろえる。`updatedAt` は変えない。
  - Log には同じ `recordId`（操作の opId）で開始の `rename` と完了の `renamed` の 2 行が残る。`rename` だけの行は途中で止まった変更で、利用者が画面の「再試行」を押すと続きから行う。過去の Log の行は書き換えない。
  - 旧名は予約しない（ほかの人が新規登録できる）。旧名のままの別の端末は、次のデータ取得時にログアウトする。大文字小文字・全角半角だけの変更なら、ログアウトせず新しい表記にそろう。
  - 共通パスワードだけで動くため、画面を通さなければ他人の名前も変えられる（既存の配合の更新と同じ水準）。
- パスワード変更後は次の API 通信で再ログインが必要になる。端末には成功時の ID とパスワードを保存する。設定画面のログアウトでパスワードとキャッシュを消去し、次回入力用の ID は残す。
- テスト用は従来どおり Script Properties の `TEST_PASSCODE` を使う（AI・開発者専用）。`.env.local` の `PAL_TEST_PASSCODE` に保存する（コミットしない）。必要な場合のみ `TEST_PASSCODE` を消して `setup()` を再実行すると作り直される。

## 所持パル（セーブ連携とスプレッドシートでの共有）

画面の「所持パル」は、Palworld のセーブから所持パル・パッシブ・場所を読み込む。ワールドのホストの画面が、読み込んだ内容をスプレッドシートに共有し、参加している人はそれを見る。セーブの構成は [SAVE_FORMAT.md](SAVE_FORMAT.md) を参照。

### 初回の導入（GAS）

- `npm run gas:push` → `npx clasp update-deployment <deployment ID>` で GAS を更新する。
- 所有者が Apps Script エディタで `setup()` を再実行し、`OwnedPals`・`OwnedWorlds`（テスト用は `OwnedPals_test`・`OwnedWorlds_test`）のシートを作る。既存のシートとデータは変えない。実行するまでは共有がエラーになる（この PC で読み込んだ所持パルは見られる）。
- 新しい権限は要らない（同じスプレッドシートを読み書きするだけ）。
- 配合牧場の共有（2026-10-08 追加）: `OwnedWorlds` に `farms` 列（牧場の ID・拠点・親の個体 ID の JSON。セルに収まるよう 200 件まで。牧場を送らない古い画面からの共有や列がないときは null〈情報なし〉として扱い、牧場の判定を出さない）を足した。GAS を更新した後、所有者が `setup()` を実行し直すと、既存のシートの末尾に列が足される（既存の列とデータは変えない。`gas/Setup.js` の `ensureSheet_`）。実行するまでも共有は動き、牧場だけが届かない（参加している人に牧場の判定が出ない）。GAS を先に更新してから画面を配信する（古い GAS は `farms` を知らないフィールドとして拒否するため）。
- 覚えているアクティブスキルの共有（2026-10-10 追加）: `OwnedPals` に `skillIds` 列（スキルの ID を `|` 区切り。1000 字まで）を足した（`OWNED_FIELDS` の末尾・`OWNED_ADDED_FIELDS`）。GAS を更新した後、所有者が `setup()` を実行し直すと、既存のシートの末尾に列が足される。実行するまでも共有は動き、スキルだけが届かない（GAS は列がなければ書かずに、空として返す）。GAS を先に更新してから画面を配信する（古い GAS は列の数が違う共有を拒否するため）。新しい GAS は、列を知らない古い画面（開いたままのページ）からの共有も受け付ける。
- `OwnedWorlds` はワールドごとに 1 行（ワールド名・ホスト名・セーブの更新時刻・共有した時刻と ID・体数・プレイヤーと拠点の一覧・配合牧場の一覧）。`OwnedPals` はパルごとに 1 行（`worldId` と、`web/js/core/owned-shared.js` の `OWNED_FIELDS` の列）。シートを直接編集しても、次に共有されたときに上書きされる。

### 設定（設定タブの「セーブ連携」）

- 連携は「＋ ワールドを登録」で、ワールドのセーブのファイルを登録する（Chrome・Edge が前提）。登録していないときは、所持パルのタブに案内だけ出す。
- 「使うワールド」で、所持パルの表示・自動の読み込み・配合の自動登録に使うワールドを選ぶ。既定の「自動」は、登録したワールドがあれば最後に遊んだワールド、なければいちばん新しく共有されたワールド。
- 登録したワールドの一覧は行ごとに開閉でき、開くとそのワールドの「配合牧場からの自動登録」（オン・オフと、登録者の対応）を設定できる。登録者は、セーブのプレイヤーが分かる、いま読み込んでいるワールドでだけ選べる。
- ホストか参加している側かは、`Level.sav` と `LocalData.sav` の更新日時で決める（`web/js/save/source.js` の `judgeRole`）。`LocalData.sav` が `Level.sav` より 10 秒以上新しい、または `LocalData.sav` しかなければ参加している側（フォルダ名はホストのワールド ID と同じ）、それ以外で `Level.sav` があればホスト。
  - ホストで保存すると 2 つはほぼ同時に書かれ、参加すると `LocalData.sav` だけが書かれる。前にホストしたワールドに参加した場合、古い `Level.sav` が残るが、`LocalData.sav` の方が新しいので参加と判定する。
  - ホスト: 読み込んだ所持パルをスプレッドシートに共有する。60 秒以上空け、その間の更新はまとめて最新を送る。
  - 参加している側: 自分のセーブは読まず、ホストが共有した同じワールドの所持パルを出す。
  - 登録していない人は、「使うワールド」で共有されているワールドを選ぶ（既定は、いちばん新しいセーブが共有されたワールド）。
- 共有されたデータは、所持パル・継承ルート・理想個体を開いたときとタブに戻ったときに読み直す（30 秒以上空ける）。
- 共有はワールドごとに丸ごと置き換える。セーブから消えたパルはシートからも消える。
- 競合したとき（同じワールドを別の PC からも共有した、など）は、セーブの更新時刻が新しい方を残す。古いセーブは GAS が受け付けず、画面は新しい方を出す。この PC で読み込んだものと共有されたものがあるときも、新しい方を出す。
- 所持パルのタブには、表示しているワールド・体数と、更新時刻（セーブの更新・共有した時刻と ID・この PC で読み込んだ時刻）を出す。
- 登録したワールドの行を開いた「共有した所持パルを削除」（ホストとして登録し、共有済みのワールドだけ出る）で、そのワールドの所持パルをスプレッドシートから消す。次にセーブを読み込んだときに、また共有される。

### セーブのファイルの登録（自動の読み込み）

- ブラウザ（Chrome・Edge）は `AppData` 配下のフォルダを開けないが、エクスプローラーからドロップした**ファイル**のハンドルは受け取れ、IndexedDB に保存して後から読み直せる（`web/js/save/handles.js`）。以前のセーブ連携ツール（ローカルの中継）は廃止した。
- 登録はワールドごとに 1 回（設定タブの「＋ ワールドを登録」で開くモーダル）。
  1. エクスプローラーでワールドのフォルダ（`%LOCALAPPDATA%\Pal\Saved\SaveGames\<Steam ID>\<ワールド ID>`）を開き、アドレス欄のパスを貼る。セーブのファイルにはワールド ID が入っていないため、パスから ID を取る。
  2. 画面に出る場所のファイルをドロップする（何回かに分けて足せる）。ホストのワールドは `Level.sav`・`LevelMeta.sav`・`LocalData.sav`（必須）と `Players` の中のファイル全部、任意で 1 つ上の `GlobalPalStorage.sav`。参加しただけのワールドは `LocalData.sav` だけ。
  3. ドロップするたびに読み込んで、ワールド名・ホスト名・体数をモーダルに出す（まだ保存・共有しない）。「保存」で登録し、読み込みと共有を始める。貼ったパスとドロップしたファイルが同じワールドかは機械では確かめられないので、ワールド名で確かめる。
- 登録したワールドは、一覧の「編集」でパスを入れた状態のモーダルを開き、足したいファイルをドロップして「保存」する。「削除」で登録を消す（最後の 1 つを消すと自動の読み込みも止まる）。
- 登録した後は、1 分ごと（タブが裏にあっても）と、所持パル・継承ルート・理想個体を開いたとき・タブに戻ったときに、登録したワールドの中から最後に遊んだワールドを選び、セーブが更新されていれば読み直す（20 秒以上空ける。1 分ごとの読み直しでは、共有された一覧は取り直さない）。別のワールドに固定するときは設定タブの「使うワールド」で選ぶ。
- 読む許可: 初めて読むとき（またはブラウザを開き直したとき）に Chrome が許可を求める。「毎回のアクセスを許可」を選ぶと、次からは確認なしで読む。許可が要るときは所持パル・設定タブに「読み込みを許可」ボタンが出る（許可のないワールドがあるときは、別のワールドを黙って選ばない）。拒否した場合は Chrome のサイトの設定で許可を戻すか、登録し直す。
- 読み込みで飛ばすのは、必須（`Level.sav`・`LevelMeta.sav`・`LocalData.sav`）以外の消えたファイルだけ（所持パルのタブに知らせる）。読めないエラー（許可・ゲームの保存中など）は失敗にし、共有もしない。必須のファイルが読めないワールドは、ホストか参加かを判定せず、共有を止める。選んでいなければ、読めるワールドのうち最後に遊んだものを読み、読めないワールドがあれば知らせる。
- 共有は、このページでホストのワールドのセーブを正常に読めたときだけ行う（開き直した直後は、保存済みのデータがあっても一度読み直す）。読み込みの途中で登録の削除を押した場合、その読み込みの結果では共有しない。
- 1 回のドロップに同じ名前のファイル（同じ場所に入るもの）が 2 つ以上あると、どれが正しいか分からないので、そのファイルはどれも受け取らない。
- 同じワールドかは、ワールド ID（フォルダ名）だけで見分ける。参加すると、自分の PC にホストのワールド ID と同じ名前のフォルダができ、`LocalData.sav` だけが書かれる。ワールドデータを仲間に渡すときにフォルダごとコピーすれば ID は変わらないので、誰がホストしても同じワールドとして扱える（前にホストしたワールドに参加すると、更新日時で参加と判定する）。フォルダ名を変えると別のワールドになる。
- 一度もホストしていないワールドに参加するときは、そのワールドの `LocalData.sav` を 1 回登録しておくと、遊んだワールドとして自動で選ばれる。
- 登録した後に仲間が増えると、その人の `Players\<ID>.sav` は登録されていない。所持パルのタブに案内が出るので、設定タブの「編集」からドロップして足す。
- IndexedDB に保存できないブラウザ（シークレットウィンドウなど）では、ページを開いている間だけ使う。
- Firefox など、ドロップからハンドルを取り出せないブラウザでは、Chrome か Edge で開くよう案内する（フォルダからの手動の読み込みは 2026-10-06 に廃止した）。
- ゲームの保存の途中で読むと失敗することがある。少し待ってから「今すぐ読み込む」を押す。
- 手元のセーブで読み込みを確かめるには `npm run check:save -- "<ワールドのフォルダ>"`（省略すると最後に遊んだホストのワールド）。

### 表示と画像

- 「タマゴも表示」（既定はオン）で、牧場などにあるタマゴも出す。「グローバルボックスを表示」（既定はオフ）で、グローバルパルボックスのパルも出す。継承ルートは、この切り替えに関係なく所持パル全体を使う（開始候補にはタマゴとグローバルボックスも含める。相手親の所持数はグローバルボックスを含め、タマゴは数えない）。
- 人間のキャラクター（密猟団・賞金首など、パルのマスターにないもの）は、ゲーム本体から取り出した日本語名とアイコン（`web/data/humans.js`・`web/img/humans/`）で出す。ゲームの更新で作り直すときは `npm run extract:humans -- "<Palworld のインストール先>"`。
- 一覧（所持パル・みんなの配合ノート）と継承ルートの候補は、件数が多くても最初から全部出す。
- パルボックスの個体は、場所に「パルボックス 3 ページ・2 行 4 列」のようにページと位置を出す（所持パル・継承ルートの個体一覧・理想個体）。継承ルートの候補の要約は「パルボックス」まで。位置は共有の `placeLabel` に入るので、参加している人には、ホストの画面が新しい版でセーブを読み直して共有した後に出る（GAS の変更はない）。
- パルの画像は図鑑と同じ（`web/img/pals/`）。ローカルで画像が出ないときは `npm run fetch:icons` を実行する（配信時は GitHub Actions が取得する）。
- 絞り込みは、所持者・場所・パル・キーワード・パル濃縮（★の数、以上）・個体値（HP・攻撃・防御、それぞれ以上）・パッシブ（すべて持つ個体）。
- キーワードは、パル名（日本語・英名・内部名）・ニックネーム・属性・パートナースキル・覚えているアクティブスキル・パッシブ（それぞれ名前と説明文）・性別（オス／メス）・タマゴ／ラッキー／アルファ・所持者・場所・預けた人（拠点の個体だけ）から探す（`web/js/core/owned.js` の `keywordFields`）。レベル・★・個体値は専用の絞り込みがあるので探さない（パッシブの説明の「+30%」などの数値は探す）。
  - 説明文も常に探すので、例えば「闇」で、闇属性のパルに加えて、パートナースキルの説明に「闇属性」が出てくるパルも出る（2026-10-10 のユーザー指示）。
  - 空白（全角も）で区切ると、すべての語を含む個体に絞る。ひらがなとカタカナ・全角と半角・大文字と小文字の違いはそろえる。
  - 一致した理由を、パッシブの下に出す（`keywordNotes`）。アクティブスキルとパートナースキルは名前か説明文で一致したとき、パッシブは説明文で一致したとき（名前は一覧に出ている）。説明文で一致したときは、名前の下に説明文を添える。
  - スキルの名前と説明文はゲーム本体から取り出したもの（`web/data/skills.js`）。ゲームの更新で作り直すときは `npm run extract:skills -- "<Palworld のインストール先>"`。名前の表にないアクティブスキルは ID のまま出す。
  - 説明文の中の、パートナースキルのレベル（パル濃縮）で変わる数値は「○」にしている（ゲームは別のデータから計算して出す）。レベルで変わる追記（「ダメージ増加：小」など）は入れていない。パッシブの説明は PalCalc のデータ（`web/data/passives.js` の `desc`）。
  - アクティブスキルは、スキルを読むようにした版でセーブを読み込み直すまで出ない（登録したファイルは、ページを開き直すと一度読み直す）。参加している人には、ホストの画面が新しい版で共有し直した後に出る。
- パッシブの見た目はゲームのパル詳細画面に合わせる。ランクの矢印と背景の三角模様はゲーム本体から取り出した画像（`web/img/passive/`）、左の帯・枠・板の色はゲーム画面から測った値を CSS で描く（ランク 1・2 は白、3 は金、4 は水色、マイナスは赤。ランク 5 は見本がないため推定）。ゲームの更新で画像を作り直すときは `npm run extract:passive-icons -- "<Palworld のインストール先>"`。
- 一覧は、設定タブで登録したワールドの行を開いた「CSV で保存」で、そのワールドの所持パルを Excel 用の CSV（UTF-8・BOM 付き）に出せる（この PC で読み込んだセーブがあればそれを、なければ共有されたものを使う）。ワールドを登録していないときは「所持パルを CSV で保存」で、表示しているワールドを出す。列は `web/js/core/owned.js` の `OWNED_COLUMNS`。
- パッシブ名のマスターを更新するには `npm run build:passives`（取得元のコミットは `scripts/sources.mjs` の PalCalc と同じ）。

### 理想個体

- 「理想個体」タブでは、目標のパル・欲しいパッシブ・個体値の目標（HP・攻撃・防御。0 は気にしない）・ケーキを選ぶと、表示しているワールドの所持パルから、配合牧場に置く ♂×♀ の組を上から並べる（下の「配合の計画」）。
- 候補は、目標と同じ種族どうしと、登録済みの配合（子が目標のもの）の親。タマゴ（孵化するまで牧場に置けない）・グローバルパルボックス・人間・性別不明の個体は使わない（切り替えはない。`web/js/core/ideal.js` の `isParentCandidate`）。産まれたタマゴは、孵化させて受け取ると候補に入る。欲しいパッシブの選択欄の所持数も、タマゴとグローバルパルボックスの個体を数えない。
- 一覧は「配合の計画」: 理想個体を作るのにおすすめの組を、配合牧場に上から置く順に、別々の個体で最大 20 組並べる（上の組に使った個体は下の組に使わない。牧場が 3 つなら上から 3 組を置く）。並べ方の切り替えはない。組は目的で 3 つに分け、この順に並べる（`web/js/core/ideal.js` の `idealPlan`・`comparePlan`。2026-10-08 のユーザー指示）。
  - 「完全体作成組」: 欲しいパッシブと個体値の目標を全部満たす子（完全体）を作れる組。2 体で欲しいパッシブがそろい、目標のある各ステータスに目標以上（キノコケーキでは目標−5 以上）の親がいて 1 個のタマゴの成功率が 0 でない組（1 回で作れる。異種の登録済み配合を含む）と、同じ種族どうしで両親とも欲しいパッシブを全部持つ（5 個以上は除く）組（子を入れ替えながら作る）。完成までのタマゴの平均（`eggs`）の少ない順。`eggs` は、世代の平均が出る組では世代の平均（この 2 体のまま続ける場合も含めて最適に選ぶので 1 / 成功率 以下）、出ない組では 1 / 成功率。
    - 世代の平均は `generationTable`（両親それぞれの「ステータスが目標に届くか」の 3 ビット・余計なパッシブの数・共有している余計なパッシブの数を状態にした確率最短路をダイクストラ法で解く。ケーキなし・スペシャルケーキでは厳密。キノコケーキ・豪華野菜ケーキは目標−6 以上を届く扱いにした目安で並べ、目標−1 以上だけを届く扱いにした上限を「多くても」として添える）。
  - 「パッシブ厳選組」: 欲しいパッシブを全部、候補のだれかが持っているときに、個体値は見ずに、欲しいパッシブを 1 体に集める組（2 体で、どちらか 1 体より多くの欲しいパッシブがそろう組。3 体以上に分かれていれば、途中まで集める組も含む）。集まる数の多い順 → 全部継ぐ確率（パッシブの条件は「全部持つ」で計算）の高い順。
  - 「個体値厳選組」: それ以外の組。欲しいパッシブを候補のだれも持たない（配合では作れない。ダイヤモンドのパッシブなど）ときは、全部この組になり、画面に「別に手に入れてください」と、そのパッシブを運ぶ経路への案内を出す。パッシブは後から手に入れる前提で見ずに、個体値の目標がそろう子が産まれるまでの平均（`talentEggs`。同じ種族なら、パッシブを見ない世代の表で子を入れ替えながら）の少ない順。
  - どの組も、同じ組み合わせで別の子も登録されている組は後ろに回し、最後は個体 ID で決める（同じ入力なら必ず同じ並び）。
  - パッシブの条件を満たす子が産まれない組（スペシャルケーキで 4 個未満の「欲しいものだけ」なら全部、パッシブを持つ親で「パッシブなし」）は置いても完成しないので出さない（`blocked`）。
  - 別々の個体は、並びの上から順に、まだ使っていない個体どうしの組を選ぶ（貪欲法。組の数を最大にする割り当てではない）。全部の組を並べ替えずに済むよう、♂ ごとに良い組を 2×20 件だけ残してから選ぶ（i 番目に選ばれる組は、その ♂ の組のうち使われた ♀〈i−1 体以下〉の組を除いた一番良い組なので、必ず残っている）。♂ の上位が上の目的の組で埋まっていれば、その ♂ の個体値厳選組の平均は求めない。キノコケーキの「多くても」は選んだ組にだけ求める。
  - 計算の時間（2026-10-08 に計測）: ケーキなしで ♂1000×♀1000 が約 0.5 秒。キノコケーキは最初の 1 個を実際の値で計算するので重く、値が 0〜100 にばらける ♂1000×♀1000 で約 0.6 秒、値が目標の近くに集まる ♂200×♀200 で約 0.4 秒（♂1000×♀1000 だと 10 秒を超えうる）。組は所持パルのデータが変わったときだけ計算し直す。
- 配合牧場の判定（`web/js/core/ideal-farms.js`）: 今この目標の組が入っている配合牧場（親が 2 体とも候補にいて、♂ と ♀ で目標が産まれる向きのもの。K か所）を、おすすめの上から K 組と比べる。置いてある組が上位 K 組にあれば「そのまま」、なければ、まだどの牧場にもない組への「交換推奨」を出す（親の片方が同じ牧場を優先し、1 体の入れ替えで済むようにする。外す個体と入れる個体〈いる場所つき〉を出す）。空いている牧場・ほかのパルを配合している牧場は見ない（何を置くかはユーザーがおすすめの順を見て決める）。一覧のカードにも「〇〇の牧場に配置中」と出す。
  - 牧場の中身は、ホストはセーブ（`snapshot.breedFarms` の親が読めた牧場）、参加している人はホストの共有（`OwnedWorlds` の `farms` 列）から読む。牧場を共有する前の GAS・画面からのデータには牧場がないので、判定を出さない。
  - 「変更あり」: 牧場の中身（対象の牧場とその組）が最後に変わったときのおすすめを基準として、この端末の localStorage（`<namespace>.idealPlan`。条件ごとに新しいものから 50 件）に残し、基準になかった組がおすすめに入ったらカードに「変更あり」と出す。牧場の中身が変わったこと（置き直した）をセーブから検知したら、そのときのおすすめを新しい基準にして印を消す。交換推奨は読み直すたびに作り直す。
- 「所持者」は「すべて」「自分の個体」「各プレイヤー」（拠点は出さない）。プレイヤーの個体は、所持者がそのプレイヤー（手持ち・パルボックス・パル次元ストレージ・持っているタマゴ）の個体と、そのプレイヤーが預けた拠点のパル（共有されたデータでは名前で照らし、同じ名前のプレイヤーが複数いれば数えない）、ホストならグローバルパルボックスの個体（`web/js/core/ideal-goals.js` の `palsOfPlayers`）。タマゴは親の候補にも完成の判定にも使わない（拠点に置かれたタマゴには最後の持ち主も入らない。手元のセーブ 14 ワールド・54 個で確認・2026-10-08）。自分の個体は、配合牧場の自動登録と同じ「登録者の対応」（なければ ID と同じ名前のプレイヤー）で決める。
- 今の条件（パル・欲しいパッシブ・パッシブの条件・個体値の目標・ケーキ）を「理想個体として登録」で名前を付けて登録できる（同じ条件は 1 つまで、100 件まで。名前は後から変えられない）。アルファの条件は 2026-10-08 になくした（前に登録したものに残っていても読まず、同じ条件になった登録は先に登録したものを残す）。登録はこの端末の localStorage（`<namespace>.ideals.<env>.<userIdKey>`）に残し、名前の変更では新しい名前へ移す。
  - 完成の判定は自分の個体だけで行う（`web/js/core/ideal-goals.js` の `ownPals`）。自分のプレイヤーは、配合牧場の自動登録と同じ「登録者の対応」（設定タブ。選んでいなければ ID と同じ名前のプレイヤー）で決め、手持ち・パルボックス・パル次元ストレージ・自分が預けた拠点のパル、ホストならグローバルパルボックスの個体を自分の個体とする（上の「所持者」と同じ `palsOfPlayers`）。タマゴは、中身が条件を満たしても数えない（孵化させて受け取ったら完成。`goalMatches`）。自分のプレイヤーが分からないときは判定しない。
  - 「登録した理想個体」の一覧で、表示しているワールドの自分の個体に条件を満たすものがいれば「完成済み」と出す（データがない・自分のプレイヤーが分からないときは「未確認」）。「呼び出す」は、URL の `g`（登録の ID）で登録した条件をそのまま開き直す。
  - 完成の通知は `web/js/ideals.js`。ワールドごとに、判定に使ったセーブの時刻より新しいデータを受けたときだけ判定し（古いデータで巻き戻さない）、そのワールドで初めて判定したとき・登録した時点で完成していたときは知らせない。未完成から完成に変わったら右上のベルで知らせ、未完成に戻ったら通知を消す。
- 理想個体のタブを開いている間は約 20 秒ごとに `owned.autoRefresh()` を呼び、孵化させて受け取ったパルも候補に入れて並べ直す（タブが裏にある間は呼ばない。ホストは 20 秒以上空けてセーブを読み直し、参加している人はホストの共有（60 秒ごと）を 30 秒以上空けて読み直す）。
- パッシブの条件は「欲しいものを全部持つ（他も可）」と「欲しいものだけを持つ」から選ぶ。所持者・条件・個体値の目標・ケーキはタブを切り替えても残る（URL には載らず、ページを読み込み直すと既定に戻る）。
- 同じ親の組み合わせで別の子も登録されている組は、目標が産まれるとは限らないため、同じ目的の組の後ろに回し、確率は目標が産まれた場合の値として出す。
- 親の性別が記録された配合（自動登録など）は、親の性別を入れ替えても同じ子が産まれるとみなし、入れ替えた向き（例: A♂×B♀ の記録なら A♀×B♂）も候補にして「性別を入れ替えた向き（未検証）」と出す。入れ替えた向きで別の子が登録されていれば、目標が産まれるとは限らない組として後ろに回す。同じ種族どうしは性別に関係しないので注記しない。ゲームで性別により子が変わるフォレーナ×クレメーオだけは、入れ替えた向きを候補にしない（`web/js/core/ideal.js` の `GENDER_DEPENDENT`）。
- 確率は、ゲームの遺伝の仕組み（`web/js/core/ideal.js` の定数。Palworld v1.0.5 で確認）で計算する（INV-2 の例外。[SOURCES.md](../data/SOURCES.md)）。ゲームの更新で仕組みが変わったら、定数とテスト（`test/core/ideal.test.js`）を見直す。
