## 2. 構造的な問題（調査の要約）

1. **同じことをする入口が 3 系統ずつある。** 探す＝配合検索・逆引き・一覧・パル詳細（同じ index を同じ `breedingCard` で出す。差は入口と件数表示の有無だけ）。登録＝常設ボタン・下書き・自動登録。知らせる＝ウィッシュリスト・理想個体の登録（どちらも端末保存・元に戻す・保存失敗警告を別実装）。
2. **全画面が縦 1 列の積み上げで、本文に sticky/fixed が 1 つもない**（固定はナビレール・トースト・浮かせたピッカーだけ）。所持パルは絞り込み 3 列 4 段（9 要素 12 操作、約 355px）＋案内 1 本で一覧が y≈630 から（撮影で 2 本目に見えた黄色の帯はダミー注入の副作用で実運用では出ない）、理想個体は条件 7 ブロックで y≈575〜670 から始まる。高さが変わる要素（読み込み中の帯・牧場の判定・不足パッシブの注記・更新の帯・パッシブのチップ列）が一覧の上に出入りして下がずれる。
3. **画面間の往復がすべて「タブ遷移＋main 全体の作り直し」**。同一画面内の選択（目標・パッシブ・開始）も `navigate` で URL を変えて `destroy → 新規生成 → replaceChildren` するため、スクロール位置とフォーカスが失われ、1 操作ごとに履歴が積まれる。所持パル→理想個体→継承ルート間の導線はゼロで 6〜8 操作かかる。
4. **説明文が「仕組みを全部書く」方針で長い**（理想個体「計算のしくみ」14 項目 1,684 字、要約行 8 要素、設定タブを文章で指す案内が 7 か所でリンクなし）。用語の揺れ（生まれる/産まれる、所持者の指す範囲、濃縮/凝縮、スキル/パッシブ、登録＝サーバ/端末）。
5. **セーブから読めているのに使っていない情報と、構造的な欠陥。** タマゴの中身（パッシブ・個体値）は読めているのに理想個体の判定に使わない。全牧場の親・タマゴ数・預けた人は normalizeOwned で捨てる。ギルドの last_online（接続中判定）・Day・Lv は読み飛ばし。**参加者は「このワールドでの自分」を設定する UI が無い**ため、ゲーム内名がノート ID と違う参加者は理想個体の完成通知が永久に「未確認」（views/owned-settings.js:302 で `players` はホストのときだけ、views/ideal.js:143 の案内先が存在しない）。
