## 全体の所見

1. **重複**: 探す（配合検索・逆引き・一覧・パル詳細）、登録（常設ボタン・下書き・自動登録）、知らせる（ウィッシュリスト・理想個体の登録）がそれぞれ 3 系統ある。設定の「データの状態」「通知」はヘッダー・ベルと重なる。

4. **ずれ**: 本文に sticky が 1 つもなく、URL が変わるたびに main を丸ごと作り直す（app.js の render）。高さを確保しない部品（件数の行・パッシブのチップ・読み込み帯・20 秒ごとの再計算）があり、表示が上下し、フォーカス・スクロール・開いた選択肢が失われる。
5. **活かし切れていない情報**: 所持パルが配合の画面に出ない。牧場のタマゴ・ケーキ・手術台・接続中の仲間は未活用。
6. **構造の欠陥**: 参加者は「このワールドでの自分」を設定できず、理想個体の完成が判定されない。参加者には「自動登録は動きません」と誤解を招く案内が出る（views/owned-settings.js:224）。
7. **INV-2 の逸脱（小）**: 自動登録の通知の本文に、配合表から求めた子（「表は X」）を出している（auto-register.js:214・219）。

## 実装の進め方

- **テーマ単位**: 1 テーマ＝1 ブランチ（`feature/<テーマ key>`。修正は `fix/…`）→ 日本語のコミット → `main` に `--no-ff` でマージ。push と配信はユーザーの確認後。
- **1 テーマの手順**: 案の詳細（フェーズ 0 で書き出したもの・別プランの F 番号の節）を読む → 現状のコードを確かめる → 振る舞いが変わる所はテストを先に直す・足す（`node --test`）→ 実装 → `npm test` → モックで画面を確かめ、基準の計測を取り直す → `web/js/release-notes.js` に 1 件（title 20 字・body 60 字以内。移動・削除した機能は「どこへ移ったか」を書く）。
- **実装は直列**（同じファイルを触るテーマが多い）。フェーズの終わりに、観点別のエージェントと Codex（読み取り専用）で差分をレビューし、直してから次へ。Codex に実装を任せるのは、小さな試しで書き込みとテストの実行を確かめてから（この環境では Codex のシェルの起動が失敗し、ファイルの読み取りは node_repl で行えていた）。
- **フェーズの区切りで報告**（変更したファイル・実行したコマンド・画面の確かめ方）し、そのまま次へ進む。
- **GAS の変更**は、仲間に共有すると決めたデータ（farm-data・save-extras、接続中の仲間を参加者に出す場合）だけ。反映（`npm run gas:push` と `setup()`）はユーザーの操作が要る。
- **全テーマ共通の受け入れ条件**
  - INV-2: 配合の候補は登録済みの記録だけから引く。配合表（breeding.js）と理想個体（core/ideal.js）を読み込める場所は、今のテスト（test/import.test.js）の制限のまま。

## 判断事項（推奨どおりに進めるもの。違う場合は承認時に指示）

1. 自動登録の通知・保留に配合表の答えを出すか → **出さない**（別プランの「予想は X」も採らない）
2. 確認回数・相手親の除外を戻すか → **戻さない**（GAS の confirm と列は触らない）
3. 手術台を計画に入れるか → **案内 → 手術分を除くリンクまで**。既定は配合だけ
4. 子の性別比を取り込むか → **今は取り込まない**
5. ゲームから取り出す画像の範囲 → **属性 9 種から順に**（作業適性・卵・ケーキ・牧場・性別まで）。Codex の画像生成は配信物に使わない
6. 空の状態の絵 → **ナビのアイコン**（AI の線画は任意）
7. 共有する配合の削除の確認 → **残す**（端末だけのものは確認なし＋元に戻す）
8. 目標の名前 → **自動（パル名＋パッシブ）**。保存のときに小さな入力で変えられる。一覧は未完成を上に
9. 見出しのキャッチコピー → **削除**（ログイン画面の INV-2 の注記は残す）
10. 個体値の保存の形 → **今の「0＝条件なし」のまま**（画面だけ D4）
11. CSV の置き場所 → **設定の「書き出し」カードにまとめる**（各タブへの移動はしない）

- ホーム画面、仲間ボード、古代の孵化器の自動登録（形式未確認）

## リスクと前提

- 規模が大きい（42 テーマ）。文言・DOM 構造を固定しているテストが多く、各テーマで期待値の更新が要る（別プラン §9 の C の一覧を正とし、ResizeObserver のモックを test/helpers/dom.js・app.test.js に足す）。文言の更新と振る舞いの回帰確認は分ける。
- render-contract は多くのビューに触れるので、先に小さく入れて全タブのテストを通してから進む。
- ヘッダーに状態・ベル・ID・（後で）パル検索が並ぶ。1 行に収まらないときの隠す順番を header-frame で決める。viewport 1100 固定のため、sticky のパネルは 2 段（約 120px）まで。
- 目標の統合（goals-merge）は端末のデータの移行を伴う。移行は繰り返しても同じ結果にし、保存に成功するまで旧データを消さない。
- 撮影で確かめられなかったもの（参加者の画面・20 秒更新で順位が変わる場面・ワールド登録済みの設定）は、roles のモックの役割切り替えと実機で確かめる。
- フェーズ 4 は実セーブ・ゲーム本体の形式に依存（項目がない・テクスチャ形式が違う場合は、その案を止めて報告）。
- Codex の 5h/1w の枠を、フェーズ末のレビューで消費する。

## 検証

- **自動**: 各テーマで `npm test`（release-notes の文字数も）、フェーズの終わりに `npm run test:perf`（20,000 行・偏った分布を追加）。
- **画面（基準との比較）**: `npm run dev` → `http://localhost:5173/?mock=1&seed=80`（所持系はフェーズ 0 の注入スクリプト）で、調査と同じ操作を繰り返して比べる。

| 操作 | 今（実測） | 目標 |
|---|---|---|
| 配合検索で親を選ぶ | 結果が 27px 下がる | 動かない |
| 継承ルート・所持パルでパッシブを足す | 下が 44px 下がる | 動かない |
| 所持パルで結果が減る絞り込み（scrollY=380） | 画面全体が 242px 動く | sticky のパネルで条件と件数を見失わない |
| 所持パルの行（129 行） | scrollHeight が 9574〜10011px で揺れる | 揺れない |
| 一覧で並べ替え（scrollY=2500） | 見ていた内容が失われ、絞り込み欄が固定されない | 固定の条件帯・先頭へ |
| 配合検索→パル詳細（scrollY=500） | 新しい画面が途中から表示 | ドロワーで開き、本文はそのまま |
| 登録モーダルで親・子を選ぶ | メモ欄が 71px・35px 下がる | 動かない |
| 理想個体でパッシブ追加／継承ルートのチップの × | フォーカスが body に落ちる | 選択欄・次の要素に残る |
| 下書きの一括登録 | layout-shift 0.13・340px 伸びる | 小さく |
| ヘッダー（scrollY=800） | ベル・同期状況が画面外 | 常に見える |

- **ブラウザでしか確かめられないこと**: 戻る／進む、日本語変換中の入力、候補を開いたままの同期、20 秒の更新で順位が変わる場面、幅 920px・1100px・拡大 125〜150%、ヘッダー・パネル・候補・トースト・ダイアログ・ドロワーの重なり。
- **シナリオ**: 参加者としてログインし「このワールドでの自分」を選ぶと、登録済みの目標が「完成済み」になる（選んだ時点で完成しているものは通知しない）。その後の共有の更新で新しく完成した目標はベルに出る。旧ウィッシュリストのデータから起動すると目標に移り、既読と通知が引き継がれる。旧 URL（`#/reverse?c=`・`#/list`・`#/drafts`・`#/wishlist`）を開くと統合後の画面に着く。
- **規模と互換**: 古い IndexedDB・古い共有データ・旧本文の通知・旧ウィッシュリスト・古い sessionStorage・旧コードのタブが混ざった状態から起動しても壊れない。
- **実データ**: フェーズ 4 は `npm run check:save -- "<ワールドのフォルダ>"` で項目を確かめてから実装し、`docs/SAVE_FORMAT.md` に書く。
- **レビュー**: フェーズごとに観点別のエージェントと Codex（読み取り専用）で差分を確認し、直してから次へ。
