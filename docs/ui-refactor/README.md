## 5. 守る制約と実装の進め方

### 5-1. 全テーマ共通の受け入れ条件

- **INV-2**（`data/SOURCES.md:23`「取り込まないもの（INV-2）」）: 配合の候補は**登録済みの記録だけ**から引く。例外は 2 つだけ — (a) 自動登録の照合に配合表を使う（`data/SOURCES.md:28`。画面には出さない）、(b) 理想個体の確率計算に遺伝の仕組みを使う（`data/SOURCES.md:40`）。配合表（`web/data/breeding.js`）を読めるのは `auto-register.js` だけ、`core/ideal.js` を import できるのは `views/ideal.js` だけ（`test/import.test.js:27-44` が固定）。新しく作るモジュールはどちらも import しない。タマゴの中身を「A×B→C」の式で出さない。

### 5-2. 実装の進め方

1. **1 テーマ＝1 ブランチ**: `feature/<テーマ key>`（例 `feature/inv2-notice`。直しは `fix/…`）。今あるブランチと名前はぶつからない（2026-10-12 に確認）。
2. **1 テーマの手順**: フェーズの文書の節と、付録の案（catalog.md の `### <ID>`・別プランの F 番号の節）を読む → 現状のコードを開いて確かめる → 振る舞いが変わる所はテストを先に直す・足す（`node --test`）→ 実装 → `npm test` → モック（`npm run dev` → `http://localhost:5173/?mock=1&seed=80`。所持パルは `Claude outputs/ui-audit-2026-10/shots/owned/inject.js` で注入。手順は [appendix/measurements.md](appendix/measurements.md) の「モックでの再現の仕方」）で画面を確かめ、計測を取り直す（ライトとダークの両方）→ release-notes に 1 件 → コミット → マージ。
3. **実装は直列**（同じファイルを触るテーマが多い）。並べて進めない。
4. **コミット**: メッセージは日本語（グローバルの規約）。これまでの形は「1 行目に変更の要約、空行、`- ` で補足」。マージは `main` に `--no-ff` で、メッセージは `Merge branch 'feature/<key>': <要約>`（今の履歴と同じ形）。末尾の帰属の行は、実装するセッションの指示に従う。文言の期待値の更新と振る舞いの回帰テストは分けて整理するとレビューしやすい。
5. **release-notes**（プロジェクトの CLAUDE.md）: 機能の追加・変更・**不具合の修正でも** `web/js/release-notes.js` の**先頭**に 1 件。**title 20 字以内・body 60 字以内**（`web/js/notifications.js:6-7` の `TITLE_MAX`・`BODY_MAX`。超えると `npm test` が落ちる。数え方は `String.length`）。`id` は `<実装した日 YYYY-MM-DD>-<slug>` で、**一度出したら変えない**。新しい順でないとテストが落ちる。**移動・削除した機能は「どこへ移ったか」を書く**。各テーマの文書に案（文字数を数えたもの）がある。
6. **push と配信はユーザーの確認の後**。勝手に `git push` しない。
7. **フェーズの終わり**: `npm test`・`npm run test:perf` → 統合プランの「検証」の表の操作で計測を取り直して基準と比べる → 観点別のエージェント（安定性・INV-2・セキュリティ・性能・テストなど）と Codex（読み取り専用。使う前に許可を取り、シェルが動くか先に試す）で差分をレビュー → 直す → **報告**（変更したファイル・実行したコマンド・画面の確かめ方）→ そのまま次のフェーズへ。
8. **GAS の変更**は、仲間に共有すると決めたデータ（farm-data・save-extras、接続中の仲間を参加者に出す場合）だけ。反映（`npm run gas:push`、列を足したときは GAS エディタで `setup()`）は**ユーザーの操作**。`web/js/core/owned-shared.js` を変えたら `npm run build:gas` で `gas/Shared.js` を作り直す（`test/core/shared.test.js` が一致を確かめる）。共有データを広げるときの決まりは phase-3-4-drawer-data.md の「0-4」。
9. **規約ファイル**（プロジェクトの CLAUDE.md・`data/SOURCES.md` など）を変えるときは、理由と影響を変更記録に書く。
10. **Codex に実装を任せる**のは、小さな試しで書き込みとテストの実行ができることを確かめてから（この環境ではシェルの起動が失敗した）。任せた結果は未信頼の入力として、`git status`・テストの exit code で確かめる。

## 7. 検証

### 7-1. 自動

- 各テーマで `npm test`（release-notes の文字数も確かめる）。
- フェーズの終わりに `npm run test:perf`（今は `test/perf/ideal.perf.js`・`route.perf.js`。1c で `owned.perf.js` を足し、20,000 行・偏った分布も測る）。ideal-calc は変える前の値を測ってから入れ、世代の表の作成と使い回しを分けて記録する。

### 7-2. 画面（基準との比較）

`npm run dev` → `http://localhost:5173/?mock=1&seed=80`（所持系は `Claude outputs/ui-audit-2026-10/shots/owned/inject.js` で注入）で、調査と同じ操作を繰り返して比べる。基準は 2026-10-11 に HEAD `ad648b7` で測った値（[appendix/measurements.md](appendix/measurements.md)）。

| 操作 | 今（実測） | 目標 | 主に直すテーマ |
|---|---|---|---|
| 配合検索で親を選ぶ | 結果が 27px 下がる | 動かない | stable-render |
| 継承ルート・所持パルでパッシブを足す | 下が 44px 下がる | 動かない | popovers・owned-toolbar |
| 所持パルで結果が減る絞り込み（scrollY=380） | 画面全体が 242px 動く | sticky のパネルで条件と件数を見失わない | owned-toolbar |

| 配合検索→パル詳細（scrollY=500） | 新しい画面が途中から表示 | ドロワーで開き、本文はそのまま | keep-state（先頭から）→ drawer・pal-detail |

### 7-3. ブラウザでしか確かめられないこと

戻る／進む、日本語変換中の入力、候補を開いたままの同期、20 秒の更新で順位が変わる場面、幅 920px・1100px・拡大 125〜150%、ヘッダー・パネル・候補・トースト・ダイアログ・ドロワーの重なり、許可の要求（実機）。

### 7-4. シナリオ

- 参加者としてログインし「このワールドでの自分」を選ぶと、登録済みの目標が「完成済み」になる（選んだ時点で完成しているものは通知しない）。その後の共有の更新で新しく完成した目標はベルに出る。
- 旧ウィッシュリストのデータから起動すると目標に移り、既読と通知が引き継がれる。
- 旧 URL（`#/reverse?c=`・`#/list`・`#/drafts`・`#/wishlist`）を開くと、履歴を増やさずに統合後の画面に着く。
- 理想個体（ideal-calc の後）: phase-1-0-ideal-calc.md の「経緯」の画像の 4 体（ゴウカブキ・欲しい 4 つ＝ダイヤモンドボディ・不死身・鬼神・冷静沈着・個体値の目標 100・ケーキなし。牧場に ♂A（欲しい 4 つちょうど・97/99/96）×♀B（同じ）、ほかに ♂C と ♀D（冷静沈着だけ・100/14/96））で、1 番が ♂A×♀D（平均 約 3,592 個。ideal-results の前は「世代を重ねて」、後は「完成まで」と出る）で、牧場が「交換推奨 → おすすめ 1 番（外す ♀B・入れる ♀D）」になる。平均が同じ組しかないときは、交換推奨も「変更あり」も出ない。

### 7-5. 規模と互換

古い IndexedDB・古い共有データ・旧本文の通知・旧ウィッシュリスト・古い sessionStorage・旧コードのタブが混ざった状態から起動しても壊れない。

### 7-6. 実データ

フェーズ 4 は `npm run check:save -- "<ワールドのフォルダ>"` で項目を確かめてから実装し、確かめた結果を `docs/SAVE_FORMAT.md` に書く。撮影で確かめられなかったもの（参加者の画面・20 秒更新で順位が変わる場面・ワールド登録済みの設定）は、roles のモックの役割切り替え（`?as=host|guest|viewer`）と実機で確かめる。

### 7-7. レビュー

フェーズごとに観点別のエージェントと Codex（読み取り専用）で差分を確認し、直してから次へ。自作した本人が自分で採点して終わりにしない（グローバルの規約）。
